# 장기요양길잡이 출시 전 RED TEAM 감사

> 이 문서는 수정 전 감사 시점의 결과다. 이후 사용자가 승인한 수정과 검증 결과는 [후속 수정 보고서](audit-followup-2026-11-05.md)를 참고한다.

감사일: 2026-11-05. 기준 커밋: `6c73a9b` 및 감사 시점 작업 트리. Expo SDK 58, React Native 0.88.1.

## A. 종합 평가

**출시 승인 판정을 내리기에는 이르다. 확인된 P0는 없지만 AI 사실 왜곡 방어와 개인정보처리방침에 P1이 있다.** 원본 우선 저장, 지연 응답 방어, 동의 없는 호출 차단 등은 자동 테스트에서 확인했으나 실제 모바일 운영 환경까지 검증한 것은 아니다.

| 영역 | 판단과 근거 |
| --- | --- |
| 전체 완성도 | 기록 작성부터 조회까지 웹에서 연결된다. 출시 인증, 개인정보처리방침, 모바일 출력 검증은 남아 있다. |
| UI와 UX | 기록 진입과 질문 화면의 주요 행동은 식별된다. 단계 불명 사용자, 비활성 AI 버튼의 이유, 장시간 처리 피드백이 약하다. |
| 기능 안정성 | 최신 작업 트리 자동 테스트 165개 통과. 원본 저장, 수정과 삭제 응답 경합, 기간 경계, 보고서 캐시를 포함한다. OS 저장 실패와 앱 강제 종료의 실기기 재현을 대신하지 않는다. |
| AI 신뢰성 | 정상 의역 허용과 일부 진단 및 수치 방어는 있지만, 도움 없음의 의미를 뒤집은 응답이 서버 검증을 통과하는 반례를 재현했다. |
| 보안 | 인증, 본문 크기 제한, 원자적 호출 제한, 본문 비로깅을 코드와 모의 테스트로 확인했다. 실제 배포 Secret, 플랫폼 로그, 운영 제한 상태는 미확인이다. |
| 출시 준비 | 테스트용 인증에서 일반 사용자용으로 전환할 정책과 메뉴 정리가 필요하다. 스토어 제출 및 실기기 합격 판정은 하지 않는다. |

이번 이어서 수행한 작업은 감사와 보고서 작성이다. 후첨으로 요청한 설정 하단 이름과 버전 표시는 이미 코드에 반영되어 있어 화면과 구현을 확인했다. 새 기능 수정, 패키지 설치, 배포, 커밋, 실제 사용자 데이터 변경, 유료 Claude 호출은 수행하지 않았다.

### 검증 환경과 증거 구분

- Computer Use로 IAB 웹 브라우저의 `http://localhost:8093`을 조작했다. 8081과 8082의 기존 휴대폰 연결용 환경은 조작하지 않았다.
- 8093 전용 origin의 가상 기록만 사용했다. 직접 작성 기록 1건과 질문형 기록 1건을 확인했다. 실제 개인정보와 운영 접근 코드는 사용하지 않았다.
- 모바일 배치는 390 × 844 웹 viewport에서 확인했다. 이는 iOS 또는 Android 네이티브 환경이 아니다.
- 화면 근거는 실제 실행 중 반환된 접근성 트리와 설정 화면 캡처다. 이번 보고서에 새로운 스크린샷 파일을 첨부하지 않았다. 저장소의 과거 스크린샷을 이번 실행 증거로 사용하지 않았다.
- 감사 중 보고서 읽기와 준비 상태 관련 파일에 별도 변경이 발생했다. 그 변경을 보존하고 최신 상태로 테스트와 정적 검사를 다시 수행했다. 최신 보고서 UI 변경은 브라우저에서 다시 전부 조작하지 않았으므로 코드 및 테스트 확인으로 구분한다.
- Expo 번들링 화면, 개발 서버 로딩, 브라우저 UI, OS 인쇄 및 공유 화면은 앱 자체 디자인 결함으로 계산하지 않았다.

## B. 발견된 문제 전체 목록

### R01. 도움 없음의 의미를 뒤집은 AI 결과가 근거 검증을 통과한다

- **심각도:** P1.
- **확인 상태:** 재현 완료. 합성 AI 응답을 실제 서버 검증 함수에 전달한 재현이다. Claude가 실제로 이 문장을 생성했다는 뜻은 아니다.
- **위치:** `workers/src/summary-evidence.js:8`, `:42`; `workers/src/protocol.js:44`; `workers/src/report-response.js`의 `validateSummaryEvidence` 호출.
- **재현:** 원문을 `혼자 식사하셨고 별도의 도움은 필요하지 않았다.`로 두고 AI 응답을 `보호자가 식사를 먹여드렸어요.`로 구성한다. `validateOutput('/summary', ...)`와 동일 문장 및 실제 기록 ID를 넣은 `validateOutput('/report', ...)`를 실행하면 모두 허용된다. 감사 터미널에서 두 경로 모두 `unsupported assistance ACCEPTED`를 확인했다.
- **사용자 영향:** 독립 수행이 직접 식사 보조로 뒤집힌 내용을 요약 및 보고서에 저장할 수 있다. 보호자가 실제 상태를 설명할 때 핵심 사실을 오인할 수 있다.
- **원인:** 도움 검증이 전적인 도움, 완전한 도움, 24시간 돌봄 등의 제한된 정규식에 집중되어 있다. 유효한 근거 ID는 문장의 의미가 해당 원문에서 도출된다는 보증이 아니다. 프롬프트의 금지 지침만으로는 응답 후 의미 검증을 대체할 수 없다.
- **권장 해결:** 정상 의역을 거부하는 단어 일치 방식으로 되돌리지 말고, 행동별 독립 수행과 도움 유무의 명시적 모순을 먼저 검출한다. 식사 보조, 이동 부축, 위생 대행 등 핵심 도움 행동의 긍정과 부정 반례를 추가한다. 판단이 불확실하면 원문 확인 대상으로 구분하고 안전한 대체 표시를 사용한다. 진단, 수치, 빈도 및 근거 ID 검증은 유지한다.
- **수정 부작용:** 부정 범위가 복잡한 한국어에서 정상 문장이 거부될 수 있다. `식사는 혼자 했지만 식기는 준비함` 같은 혼합 사례와 의역 허용 사례를 함께 회귀 검증해야 한다. 별도 AI 검증 호출은 비용과 시간을 늘리므로 자동으로 전제하지 않는다.

### R02. 앱에서 접근 가능한 정식 개인정보처리방침이 확인되지 않는다

- **심각도:** P1, 출시 전 제출 요건 미충족.
- **확인 상태:** 코드상 확인. 앱과 설정 검색 기준이다. 스토어 콘솔에 외부 문서가 등록되어 있는지는 확인 불가다.
- **위치:** `src/features/settings/app-notices-screen.tsx`; `src/app/(tabs)/settings.tsx`; `src/features/records/ai-controls.tsx`.
- **재현:** 설정의 앱 안내사항을 확인한다. 이용 안내, 기기 보관, 제도 확인은 있으나 개인정보처리방침으로 표시된 문서나 링크, 처리자 문의 창구, 외부 AI 처리 및 보관과 삭제 정책을 포괄하는 경로가 없다.
- **사용자 영향:** 동의 팝업을 닫은 뒤 전체 데이터 처리 정책을 확인하기 어렵다. 스토어 제출에도 문제가 된다.
- **원인:** AI 외부 전송 동의는 구현됐으나 정식 처리방침과 공개 경로가 별도로 준비되지 않았다. 동의 팝업은 처리방침 전체를 대신하지 않는다.
- **권장 해결:** 실제 운영 주체, 문의 방법, 처리 항목과 목적, Cloudflare와 Anthropic 전달, 보관 및 삭제, 동의 철회, 기기 저장과 공유 파일의 범위를 반영한 공개 문서를 마련하고 설정과 스토어에 연결한다. 외부 서비스의 실제 계약 및 처리 조건을 확인한 내용만 기재한다.
- **수정 부작용:** 문서 내용과 운영 환경이 불일치하면 오히려 잘못된 고지가 된다. 정책과 앱 동작 및 스토어 데이터 공개를 함께 관리해야 한다.

Apple은 앱 내 및 스토어 메타데이터의 처리방침 링크와 보관 및 삭제 설명을 요구한다. Google Play도 앱 내 처리방침과 콘솔 링크, 처리 주체와 보관 및 삭제 정책 등을 요구한다. 이는 한국 법률 전반에 대한 적법성 판단은 아니다. [Apple 5.1.1](https://developer.apple.com/app-store/review/guidelines/#privacy), [Google Play 사용자 데이터](https://support.google.com/googleplay/android-developer/answer/10144311?hl=ko).

### R03. ‘기록과 설정 모두 삭제’의 범위에 접근 코드와 앱 소유 PDF가 포함되지 않는다

- **심각도:** P2.
- **확인 상태:** 코드상 확인. 실제 사용자 초기화는 실행하지 않았다.
- **위치:** `src/features/reset/settings-reset.tsx:13`; `src/features/reset/controller.ts:14`; `src/features/records/ai-credentials.ts`; `src/features/records/report-pdf.ts`.
- **재현:** 초기화는 AsyncStorage의 `care-diary:` 키를 제거한다. 접근 코드는 별도의 SecureStore 키 `care-diary-ai-access`에 저장되고, iOS 파일 저장은 Documents의 `reports`에 PDF를 남긴다. 초기화 컨트롤러는 이 두 저장소를 정리하지 않는다.
- **사용자 영향:** 모든 설정과 자료를 지웠다고 생각해도 인증 정보와 앱이 보유한 민감한 PDF가 남을 수 있다. 동의 값은 삭제되므로 이것만으로 자동 AI 요청이 재개되는 것은 아니다.
- **원인:** 초기화 범위가 AsyncStorage와 알림 중심으로 구현되어 있다.
- **권장 해결:** ‘앱이 관리하는 자료’의 삭제 범위를 정의하고 SecureStore와 앱 전용 보고서 디렉터리를 포함하거나 남는 항목을 명확히 안내한다. 사용자가 외부에 복사하거나 공유한 파일은 구분한다.
- **수정 부작용:** 보존을 기대했던 접근 코드와 파일이 사라질 수 있다. 삭제 확인 문구, 실패 복구, 잘못된 디렉터리 삭제 방지를 함께 검증해야 한다.

### R04. 일반 사용자의 AI 동의 관리가 개발자 메뉴에만 있다

- **심각도:** P2, 출시 메뉴 전환 과제.
- **확인 상태:** 실제 메뉴 재현 완료 및 코드상 확인.
- **위치:** `src/app/(tabs)/settings.tsx:16`; `src/features/settings/developer-settings-screen.tsx`.
- **재현:** 설정 → 개발자 설정 → AI 이용 설정으로 이동한다. 첫 실행 테스트와 가상 자료는 `__DEV__` 조건에 있지만 개발자 설정 진입과 그 안의 AI 설정은 출시에서도 표시되는 구조다.
- **사용자 영향:** 출시 시 개발자 메뉴 전체를 숨기면 개인정보 동의 철회 경로도 사라진다. 현재 그대로 출시하면 일반 사용자가 개발자 메뉴에서 동의와 인증을 관리해야 한다.
- **원인:** 테스트용 메뉴 분리와 일반 이용자의 개인정보 관리 경로가 아직 분리되지 않았다.
- **권장 해결:** 출시에서는 테스트 기능을 숨기되 AI 이용과 동의 철회는 일반 설정에서 항상 접근할 수 있게 한다. 테스트 기능이 존재한다는 사실 자체를 결함으로 보지는 않는다.
- **수정 부작용:** 경로 중복이나 기존 링크 단절이 발생할 수 있다. 기존 개인정보 상태를 유지하고 개발 및 출시 빌드를 각각 확인해야 한다.

### R05. 현재 단계를 모르는 사용자가 초기 선택에서 진행하기 어렵다

- **심각도:** P2.
- **확인 상태:** 재현 완료.
- **위치:** `src/features/start/stage-screen.tsx:18`; `/stage`.
- **재현:** 첫 실행 흐름 → 내 상황부터 확인하기. 신청 전, 방문조사 전, 판정 전, 결과 수령의 네 단계 중 하나를 직접 선택해야 한다. ‘잘 모르겠어요’ 또는 불확실한 상황을 풀어주는 경로는 이 화면에 없다. 코드의 문답형 발견 흐름은 `review=discovery`일 때 별도로 진입한다.
- **사용자 영향:** 신청과 방문조사 또는 결과 통지의 차이를 모르는 보호자는 추측으로 고르거나 멈추게 된다. 잘못 선택하면 안내 내용도 맞지 않을 수 있다.
- **원인:** 기본 시작 경로가 단계 변경용 직접 선택 화면을 사용한다.
- **권장 해결:** 네 단계 선택은 유지하면서 판단을 돕는 짧은 질문 또는 ‘단계를 모르겠어요’ 경로를 제공한다. 어느 방식을 기본으로 할지 합의 후 기존 분기와 저장 정책을 재사용한다.
- **수정 부작용:** 이미 단계를 아는 사용자의 입력 수가 증가할 수 있다. 직접 선택을 계속 제공해야 한다.

### R06. 상세 화면의 비활성 요약 버튼에 사용할 수 없는 이유가 없다

- **심각도:** P2.
- **확인 상태:** 재현 완료.
- **위치:** `src/features/records/ai-controls.tsx:50`; 기록 상세.
- **재현:** 동의하지 않았거나 철회한 상태로 저장된 기록을 연다. ‘아직 AI 요약을 만들지 않았어요.’ 아래 ‘요약 만들기’가 비활성화되어 있지만 그 자리에서 이유를 알 수 없다.
- **사용자 영향:** 오류나 미구현 기능으로 오해하기 쉽다. 개발자 설정을 모르는 사용자는 해결 경로를 찾기 어렵다.
- **원인:** 동의 여부와 서버 주소를 버튼 조건에 사용하지만 해당 상태 설명은 생략되어 있다.
- **권장 해결:** 설정 카드와 코드 관리 UI를 다시 넣지 말고 ‘AI 이용 동의가 꺼져 있어요’ 또는 ‘서버 설정이 필요해요’ 같은 짧은 상태만 표시한다. 설정 화면 이동을 강제하지 않는다.
- **수정 부작용:** 반복 안내가 늘 수 있으므로 한 줄 설명으로 제한한다. 기존 원문 표시와 대체 요약은 유지한다.

### R07. 긴 보고서 생성 중 살아 있다는 피드백이 부족하다

- **심각도:** P2.
- **확인 상태:** 코드상 확인. 장시간 실제 Claude 호출 및 앱 프리즈는 이번 감사에서 재현하지 않았다.
- **위치:** `src/features/records/reports-screen.tsx:67`, `:74`; `src/features/records/ai-client.ts`의 90초 타임아웃; `workers/src/index.js:45`의 75초 타임아웃.

- **수정 부작용:** 취소 후 늦은 응답이나 중복 생성 처리가 추가로 필요하다. 무분별한 자동 재시도로 비용을 늘리지 않아야 한다.

### R08. 앱을 장기간 다시 열지 않으면 돌봄 알림 예약이 소진된다

- **심각도:** P2.
- **확인 상태:** 코드상 확인. 30일간 기기를 방치한 실험은 하지 않았다.
- **위치:** `src/features/notifications/planner.ts:23`; `src/features/notifications/provider.tsx:30`.

- **원인:** 기한이 있는 일회성 예약을 전경 동작으로 보충하는 구조다.
- **권장 해결:** 기록한 날 제외라는 현재 정책과 반복 알림의 제약을 비교하고 장기 보장 범위를 정한다. 반복 예약이나 예약 보충 설계를 선택한 뒤 OS 제한과 중복 알림을 실기기에서 검증한다.
- **수정 부작용:** 단순 반복 알림으로 바꾸면 이미 작성한 날에도 알림이 올 수 있다. 정책 변경을 먼저 결정해야 한다.

## F. 수정 우선순위와 독립 작업 단위

1. **AI 사실 왜곡 회귀 묶음:** 도움 유무 및 독립 수행 모순 반례와 정상 의역을 함께 테스트하고 R01을 해결한다. 원본, 인증 및 저장 구조는 유지한다. 서버 검증을 바꾸면 Workers 재배포가 필요하다.
2. **처리방침과 공개 경로:** 운영 데이터 흐름을 확인하고 R02의 문서, 앱 링크, 문의 및 스토어 공개를 일치시킨다.
3. **삭제 범위 정리:** 접근 코드, 앱 소유 PDF, 외부 공유 파일을 구분해 R03의 정책과 초기화 실패 복구를 구현한다. 실제 사용자 자료로 테스트하지 않는다.
4. **출시 AI 관리 메뉴:** 일반 설정의 동의 관리 경로를 확보한 다음 개발자 메뉴를 출시에서 분리한다. 동의 상태를 초기화하지 않는다.
5. **운영 인증과 이용량:** R09 정책을 먼저 확정한 뒤 서버 인증, 작업별 한도, 중복 생성과 삭제 후 생성 정책을 구현한다. 로컬 캐시를 서버 이용권으로 취급하지 않는다.
6. **알림 장기 동작:** R08의 미실행 기간과 기록 완료일 제외 정책을 결정하고 iOS 및 Android에서 검증한다.
7. **대기와 비활성 이유 안내:** R07과 R06을 작은 UI 변경으로 개선한다. 가짜 진행률과 무한 재시도는 추가하지 않는다.
8. **초기 단계 판단 보조:** R05를 기존 문답 경로 재사용 중심으로 개선하고 네 단계 회귀 테스트를 유지한다.
9. **릴리스 성능 계측:** R11을 90건 및 장기 누적 가상 자료로 측정한다. Metro 로딩 퍼센트와 릴리스 실행 성능을 구분한다.
10. **출시 프로필 및 기기 검수:** R10, R12와 아이콘, 서명, 빌드 번호, 사용자 글씨 확대, 실제 PDF 및 알림을 확인한다.

이 순서는 수정 제안이며 이번 감사에서 해당 구현을 수행하지 않았다.

### 보안 및 비용에서 확인한 경계

- Claude 키를 앱 공개 환경변수로 사용하는 코드 경로는 확인되지 않았다. 앱에는 중계 주소와 개별 접근 코드 경로가 있다. 실제 Secret 값이나 운영 키는 열거나 출력하지 않았다.
- 서버 모델은 서버 변수로 설정한다. 앱 화면에 특정 모델명을 표시하는 구조가 아니다.
- 인증과 제한을 CORS나 앱 고정 문자열만으로 해결하지 않는다. 토큰 해시, 서버 Secret과 Durable Object 카운터를 사용한다. Origin이 없는 네이티브 요청에도 인증은 필요하다.
- 요청은 96,000바이트, 최대 300건, 기록당 20,000자 제한이며 보고서 기간은 최대 90일이다. 초과 원문은 조용히 잘라 보내지 않고 오류로 안내한다. ‘90일이면 모든 기록량을 처리할 수 있다’는 보증은 아니다.
- 현재 서버 기본 전체 상한은 일 100회이며 설정값은 최대 500회로 제한된다. 개별 요청 수와 공급자 비용은 같지 않다. 실패 요청도 제한을 소비할 수 있고 검증 요청도 공통 카운터를 사용한다.
- 서버 코드에서 원문, AI 응답 및 키를 console로 남기는 경로는 확인하지 못했고 Wrangler observability는 꺼져 있다. 플랫폼의 실제 계정 로그 및 보관 설정은 별도 확인 대상이다.
- 무료 Workers의 CPU 한도는 10ms다. 네트워크 대기는 CPU 시간에 포함되지 않으므로 ‘20초 이상 기다림’을 곧바로 CPU 초과라고 판단할 수 없다. 다만 JSON 처리와 검증의 실제 CPU는 측정하지 않았으므로 긴 기록 처리의 무료 플랜 적합성을 확정하지 않았다. [Cloudflare Limits](https://developers.cloudflare.com/workers/platform/limits/).
- 이전 감사 차수의 npm audit 결과는 moderate 20건, high 및 critical 0건이었다. 주로 빌드 도구 의존성으로 분류했으며 모바일 런타임 공격으로 입증한 것은 아니다. 이번 이어서 수행한 차수에서 최신 취약점 DB를 다시 조회하지 않았고 패키지 자동 수정은 하지 않았다.

### 남은 수동 검증

1. iPhone과 Android의 네이티브 cold start 및 강제 종료 뒤 동의, 코드, 원문, 보고서 복원. 철회 후 실제 네트워크 요청 0건 확인.
2. 64자리 코드 붙여넣기, iOS 완료 키 및 빈 공간 터치로 키보드 닫기, 작은 화면에서 등록 버튼 접근. 현재 코드의 키보드 처리 존재만으로 기기 검증 완료라 하지 않는다.
3. 실제 운영 인증을 이용한 가상 원문 AI 요약과 7일, 30일, 90일 보고서. 비용 승인을 포함한 별도 검증이 필요하다. 이번에는 유료 Claude 요청을 하지 않았다.
4. 실제 PDF 생성 및 열기, 한글 글꼴, 긴 문장, 다중 페이지, 제목 고립 여부, iOS 공유 및 파일 앱 저장, AirPrint, Android 인쇄와 디렉터리 선택, 각 취소 및 실패 동작.
5. 네 단계의 안내부터 홈과 다음 행동까지 전부 실제 모바일 조작. 현재 전체 분기 자동 테스트는 통과했지만 이번 Computer Use 실측은 방문조사 전 중심이다. 방문 준비 체크리스트와 답변 준비의 모든 문항, 조사 후와 판정 후 안내를 실제 조작 완료로 간주하지 않는다.
6. 알림 권한 최초 승인 및 거절, 시스템 설정에서 철회, 재부팅, 앱 미실행, 시간대 및 날짜 변경, 방문 전날과 당일 경계.
7. VoiceOver와 TalkBack의 선택 상태 및 읽기 순서, 확대 글씨, 대비, 가로 및 작은 화면과 실제 고령 사용자 과제 수행.
8. 저장 중 디스크 부족, 강제 종료, 연타, 초기화 실패 복구의 네이티브 통합 시험. 원본 삭제 및 초기화는 실제 사용자 자료로 시험하지 않았다.
9. Cloudflare 운영 환경의 동시 요청 제한, CPU p95와 p99, 무료 할당량, 장애 및 예산 알림, Secret 및 로그 설정. 로컬 테스트는 실제 인프라 측정을 대신하지 않는다.
10. 출시 빌드의 최초 실행, 화면 전환 및 장기 기록 저장 성능. Expo Go 반복 리로드 퍼센트 저하는 Metro와 개발 환경 계측이 별도로 필요하며 현재 원인 미확정이다.
11. 개인정보처리방침과 스토어 데이터 공개, 설치 아이콘 및 이름, 서명과 영구 식별자. 제도 문구의 공식 최신 근거 전체와 한국 개인정보 관련 법률 검토는 완료하지 않았다.
12. 첫 실행 테스트 중 `/care-reports` 직접 진입의 격리 여부. 해당 경로가 `_layout.tsx`의 명시적 `!testing` 보호 목록에 없다는 점은 추가 확인 대상이다. 실제 우회 재현 없이 데이터 노출 취약점으로 확정하지 않았다.
