# 종합 보고서의 안전한 형식 보정 (2026-11-04)

## 문제와 개선

기존 검사는 중복 ID, 빈 제목, `repeated` 메타데이터 누락, 문단 배열 형태의 본문과 2500자를 넘는 본문을 모두 거부했다. 일부는 내용을 바꾸지 않고 정리할 수 있으므로 새 `report-response.js`에서 먼저 정상화한 다음 중요한 검사를 수행한다.

다음은 안전하게 처리한다.

- 근거 ID 중복과 바깥 공백: 중복 제거 및 trim.
- 제목 누락/공백: 본문 순서에 맞는 기본 제목 적용.
- `heading`/`content`: 각각 `title`/`text`로 정리.
- 문자열 문단 배열: 순서대로 모두 연결. 일부 문장을 삭제하지 않는다.
- `repeated` 누락: false. 실제 반복 서술이 없는 단일 기록에서 true만 잘못 왔다면 false로 정리.
- 전체를 감싼 JSON 코드 블록과 바깥 따옴표, 마침표: 기존 안전 보정 유지.
- 본문 2500자 상한: 항목당 8000자, 전체 24000자의 비정상 응답 방지 상한으로 완화. 상한 초과 시 잘라서 저장하지 않는다. 앱의 읽기/저장 검증도 같은 한도를 적용한다.

## 짧은 근거 참조

AI 요청에만 원래 ID 대신 `R1`, `R2` 등 짧은 참조를 쓴다. 본문과 날짜, 유형은 변경하지 않는다. 서버 메모리에서만 참조표를 만들고, 응답 검증 시 원래 ID로 되돌린다. 앱의 저장 데이터 구조와 근거 원문 링크는 그대로다. 응답의 R1/r1/숫자 1 같은 안전하게 대응 가능한 표기도 동일 표로 해석한다. 범위 밖 참조는 거부한다.

첫 번째 종합 본문과 확인 범위 항목에 명시된 `recordIds:["ALL"]`은 전체 분석 대상을 뜻한다. 서버가 실제 입력의 모든 ID로 확장한다. 다른 개별 양상에 ALL을 붙이면 거부한다. AI가 ID를 아예 생략한 경우 임의로 ALL을 붙이거나, 없는 ID를 버린 뒤 근거를 추측하지 않는다.

긴 ID 재출력을 줄여 형식 오류와 응답 크기를 줄이는 목적이다. 실제 모델의 속도가 얼마나 좋아지는지는 배포 후 별도로 측정해야 한다.

## 계속 차단하는 내용

- 존재하지 않는 기록 ID, 근거 누락과 분석 대상의 완전한 근거 누락.
- 단일 기록만 연결한 본문에서 근거 없이 반복/여러 날짜를 주장하는 경우. 단, 원문 한 건에 두 번의 도움처럼 실제 여러 사건이 명시되어 있으면 그 횟수는 보존하며, 이를 여러 날짜의 기록으로 바꾸지는 않는다.
- 인용한 원문에 없는 주요 진단/상태 용어, 전적인 도움 등 도움 확대, 매일/항상 등의 빈도 확대, 새로운 횟수나 수치와 장기요양등급 예측.
- 본문이 없거나 문자/문단으로 읽을 수 없는 응답, 손상된 JSON, 과도한 전체 크기.

보고서에도 기존 고위험 추가 검사기를 적용하되 각 항목이 인용한 원문만 비교한다. `팔과 등을 받침 → 부축`, `두 번 → 2차례` 같은 일반 의역을 허용하며 원문 단어의 일치율로 거부하지 않는다. 한글 숫자, 동등한 시간 단위와 절반/50%는 정규화한다.

이 검사는 알려진 고위험 추가와 구조 오류를 막는 보수적인 규칙이다. 모든 진단명, 부정/추측의 변화, 같은 숫자가 다른 행동에 잘못 붙은 경우나 반복 사례의 의미까지 완벽하게 판별하지는 못한다. 원문 대조와 참고자료 고지를 유지하며 결과의 사실성을 자동 보증한다고 표시하지 않는다.

## 실패와 저장

실패 사유를 `report-structure`, `report-title`, `report-text`, `report-evidence-missing`, `report-evidence-unknown`, `report-repetition`, `report-medical`, `report-assistance`, `report-frequency`, `report-count`, `report-grade` 등으로 구분한다. 앱은 안전한 사유 코드만 한국어로 표시하고 원문/AI 응답/키를 로그나 오류에 노출하지 않는다.

원본 저장과 기존 보고서는 바꾸지 않는다. 실패한 보고서를 일부만 저장하거나 자동 재호출하지 않는다. 기존 수동 생성과 저장본 재사용, 삭제 정책, PDF 기능을 유지한다. 이번 처리는 모델을 추가 호출하지 않으며 계정별 API 제한을 변경하지 않는다.

## 검증

- 정상 종합 서술, 선택 메타데이터 누락과 중복 참조는 통과.
- 기존 2500자 한도를 넘는 가상 본문이 온전하게 저장되고 PDF HTML에 남는지 확인.
- 짧은 ID 요청, 원래 ID 복원, ALL 확장을 중계 서버 경로로 검사.
- 없는 ID, 범위 밖 참조, ID 누락과 분석 대상 누락은 거부.
- 원문에 없는 치매, 세 번의 도움, 모든 동작을 대신함, 매일의 부축, 등급 예측과 한 기록의 반복 주장은 거부.
- 원본 저장, 동의/접근 코드, 기존 요약/보고서와 PDF 회귀 검사를 함께 실행.

테스트는 가상 자료와 모의 Claude 응답을 사용했다. 실제 실패했던 서비스 응답을 복구해 검증하거나 실제 Claude에 개인정보를 보내지 않았다. 실서비스 실패의 정확한 과거 원인은 과거 응답의 세부 사유 없이 확정할 수 없다. 새 코드부터 실패 항목을 구분할 수 있다.

전체 회귀 테스트 160개, lint와 타입 검사가 통과했다. 최대 크기에 가까운 300건 가상 기록의 Node 로컬 모의 벤치마크 평균 CPU는 약 1.64ms/회였으나, Cloudflare 실측이나 Claude 생성 시간 검증을 뜻하지 않는다.

## 변경 및 배포

주요 변경: `workers/src/report-response.js`, `workers/src/protocol.js`, `workers/src/writing.js`, `workers/src/index.js`, `src/features/records/ai-model.ts`, `src/features/records/ai-client.ts`, 관련 테스트.

**Workers 재배포와 앱 새로고침/업데이트가 모두 필요하다.** 서버에서 짧은 ID를 실제 ID로 되돌리므로 앱은 원래 저장 형식을 유지한다. 이번 작업에서 실제 배포는 수행하지 않았다.
