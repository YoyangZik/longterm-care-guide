# 로컬 알림 구현과 검증

## 구현 내용

- Expo ~58.0.22와 SDK 호환 expo-notifications ~58.1.7 사용. 원격 푸시, 토큰 발급, 서버, AI 호출 없음.
- 기본값은 모두 꺼짐. 기록은 매일 20:00, 방문은 전날 19:00을 제안하며 확정 때만 필요한 권한 요청. 거절 후 자동 재요청 없음.
- 첫 완료 기록 저장과 방문 대기 단계의 첫 유효 일정 저장 직후 각각 한 번만 제안. 안내 이력은 표시 전에 영속화하며 동시에 다른 안내가 있으면 큐에 쌓지 않음. 웹과 첫 실행 체험에서는 제안과 권한 요청 없음.
- 설정에 사용 여부, 시간, 권한 차단 상태, 일정 없음 설명 및 명시적인 기기 설정 열기 제공.
- 30일분 날짜별 단발 기록 알림과 최대 한 개 방문 알림. 총 최대 31개로 유지. 완료 기록의 날짜는 제외하고 작성 중 기록은 제외하지 않음. 같은 날짜 방문 알림 우선.
- 일정 변경, 삭제, 완료 표시 또는 방문 대기 단계 이탈, 설정 변경, 앱 시작, 복귀, 실행 중 분 경계 확인으로 예약 차이를 반영. 삭제할 때도 이 앱의 owner 표시가 있는 예약만 관리.
- 설정, 안내 이력, 예약 식별자와 이미 지난/완료된 기록 날짜를 별도 care-diary:notifications:v1 키에 저장. 기존 기록 및 일정 키는 보존.
- 이미 시간이 지난 예약 날짜는 시간 변경 후에도 다시 생성하지 않음. 과거 예약을 새 즉시 알림으로 변환하지 않음.
- 알림 내용에는 요청한 일반 제목과 본문만 포함. 내부 payload도 종류, 날짜와 소유자만 포함하며 이름, 건강 상태, 기록 본문 없음.
- 기록 알림은 /records 작성 방식 선택으로, 방문 알림은 현재 /home 체크리스트로 이동. 오래된 방문도 현재 홈으로만 이동. 작성 화면에서는 진입을 보류하고 기존 저장/이탈 흐름 뒤에 처리. 저장소를 변경하는 알림 진입 로직 없음.
- 기존 앱에는 전체 사용자 데이터 삭제 UI가 없음. resetNotifications()를 제공하여 향후 전체 삭제 흐름에서 데이터 삭제 전에 호출 가능. 개발용 첫 실행 체험은 원래 데이터와 실제 알림 설정/예약을 건드리지 않음. 소스 초기화용 scripts/reset-project.js는 사용자 데이터 초기화가 아니므로 변경하지 않음.

## 실제 기기 확인 방법과 제약

1. Expo Go에서 npm run start:go 실행 후 프로젝트를 전체 Reload. SDK 58 공식 문서상 로컬 알림은 Expo Go에서 사용 가능. 설치된 Expo Go가 SDK 58을 지원해야 함. 웹은 로컬 알림 미지원.
2. 실제 앱에서 첫 기록을 직접 작성하거나 질문으로 작성해 저장. 안내 거절 후 다음 저장에서 반복되지 않는지, 수락 후 시간 확정 전 시스템 권한을 요청하지 않는지 확인.
3. 설정에서 몇 분 뒤로 시간 설정 후 잠금/백그라운드 상태의 일반 문구 확인. 그 전에 오늘 기록을 저장했으면 당일 알림이 없어야 함. 별도 깨끗한 기기 데이터로 미완료 기록만 있는 날도 확인.
4. 내일 방문 일정과 오늘 앞으로 남은 방문 알림 시간을 설정해 기록 알림이 같은 날 제외되는지 확인. 일정 수정/삭제/단계 변경 후 이전 알림이 남지 않는지 확인. 예정 시각이 지난 일정은 즉시 보내지 않아야 함.
5. 앱 재실행, OS 권한 철회 및 복구, 시간대 변경 후 앱 복귀로 상태 확인. 실행 중/백그라운드/종료 상태 각각에서 알림을 눌러 경로 확인. 편집 중에는 진입을 보류하며 기록이 보존되는지 확인.
6. 독립 앱의 권한, config plugin, Android 채널 및 재부팅, 실제 앱 ID의 완전 종료/콜드 스타트, 출시 스플래시 검증에는 별도 development/release 빌드 필요. Expo Go는 프로젝트 독립 앱이 아니므로 이 검증을 대체하지 못함.
7. 개발 빌드가 필요하면 npx expo install expo-dev-client 후 npx eas-cli@latest build:configure, npx eas-cli@latest build --profile development --platform android (iOS는 --platform ios), 설치 후 npx expo start --dev-client 사용. 실제 빌드/가입/결제는 이번 작업에서 수행하지 않음. iOS 서명은 Apple 개발자 계정 조건에 따름.

기록 알림은 앱을 열 때마다 앞으로 30일분을 채운다. 30일 이상 앱을 열지 않으면 이후 기록 알림은 유지되지 않는다. 방문 알림은 현재 일정의 전날 한 건으로 별도 예약한다. 시간대 변경은 앱 실행/복귀 시 재계산하며 앱이 종료된 동안의 시간대 변경은 즉시 반영을 보장하지 않는다. Android는 SDK 58 bestEffort 전달을 사용하며 정확한 알람 특별 권한을 추가하거나 자동 설정 이동을 하지 않는다. OS 절전, 알림 요약, 집중 모드 등에 따라 지연/비표시될 수 있다. OS가 이미 전달한 알림을 재발송하지 않으며, OS 자체의 지연 전달을 앱이 종료된 상태에서 완전히 통제할 수는 없다.
