# 상황별 돌봄기록

## 화면

- `/records`: 새 방식 선택 → 유형 → 구체적 상황(식사·위생·배변만) → 입력/질문 → 미리보기 → 저장.
- `/records?draft=ID`: 저장한 작성 위치와 답변 복원.
- `/records?view=ID`: 작성 방식에 관계없는 전체 조회·유형/본문 수정·삭제 확인.
- 기록 탭 첫 화면: ‘오늘의 돌봄기록 남기기’ / ‘돌봄기록 돌아보기’ 두 진입 카드.
- `/records-review`: 오늘을 포함한 최근 7·30·90일(기본 30일)·전체 기간과 여섯 유형별 기록 건수, 선택 유형의 날짜·한 줄 미리보기 목록.
- `/records-calendar`: 돌아보기의 캘린더 아이콘으로 진입. 기간 필터와 독립적으로 날짜별 저장 기록을 조회하고, 더보기에서 작성 중 기록을 연다.
- 홈·기록 탭의 새 작성 버튼은 항상 새 기록의 방식 선택 화면을 연다.

## 저장과 호환

기존 `care-diary:care-records:v1`은 수정하지 않는다. `care-diary:situation-records:v2`에 첫 접근 시 기존 일지와 작성 중 기록을 공통 형식으로 가져오며 `legacyOriginal`로 원본 전체를 함께 보존한다. 기존 일지는 여러 영역을 포함할 수 있으므로 대표 유형은 ‘기타’로 가져오고 사용자가 수정할 수 있다. 질문/원문/수정 이력은 원본 스냅샷에도 남는다.

새 기록은 고유 ID별로 저장하며 날짜당 건수 제한이 없다. 날짜는 시작 당시 기기 현지 날짜, 생성 시각은 최초 생성 시각을 고정한다. 수정 시각과 최초 저장 시각을 별도로 둔다. 자동 저장은 350ms 후 실행하며 뒤로가기·백그라운드 전환 시 대기 저장을 처리한다. 저장 실패는 오류로 노출한다. 저장 버튼 연타는 화면 잠금과 ID별 직렬 저장으로 중복을 막는다. 삭제 ID는 tombstone으로 남겨 늦은 자동 저장이 기록을 되살리지 못하게 한다.

## 문답과 본문

`situation-model.ts`의 질문 데이터가 공식 자료에서 참고한 영역과 연결된다. 근거는 기존 검토 자료의 인정조사 영역이며 공식표 자체나 평가 점수를 재현하지 않는다. 모든 유형에서 구체적인 상황·실제 도움을 선택지로 묻는다. 기타는 상황·도움의 두 질문, 그 밖에는 상황·어려움·도움을 묻고 실제 도움을 선택한 경우에만 경과를 더 물어 2~4개 질문으로 진행한다. 어려움과 도움은 복수 선택할 수 있고, 없음/확인 못 함은 단독 선택한다. 필요할 때만 직접 입력이나 추가 설명을 펼친다. 선택하지 않은 다른 상황의 질문은 하지 않는다.

선택지는 지정한 문장으로, 자유 입력은 원문 그대로 줄바꿈으로 연결한다. 질문에 답하지 않은 사실·추정·횟수·진단은 넣지 않는다. 질문 스냅샷과 답변은 본문과 함께 저장한다. 유형/세부 상황 변경 시 이전 문답을 초기화하지만, 이미 손으로 편집한 본문은 자동 덮어쓰기하지 않고 미리보기에서 유지/재정리를 선택하게 한다. 저장된 기록의 유형과 본문 수정은 별도 작성 방식 없이 공통 편집 화면을 쓴다.

## 요약의 의미

기간·유형에 해당하는 저장된 기록만 집계한다. 날짜는 수정일이 아닌 원래 기록 날짜를 사용하며 같은 날 복수 기록은 개별 집계한다. 0건인 유형도 표시한다. 직접 기록과 본문을 편집한 기록은 현재 본문의 첫 문장을 추출한다. 질문 기록은 본문이 생성 결과와 같은 경우에만 선택한 상황과 실제 도움을 그대로 연결한다. 부정·불확실성·미관찰 답변은 바꾸지 않으며 한 줄이 길면 화면에서 말줄임 처리한다. 원문은 상세 화면에 보존한다. 기록 건수는 증상 발생 횟수나 필요 도움의 정도를 의미하지 않는다. AI 분석·점수·등급·PDF·의학적 판단은 구현하지 않는다.

## 기기에서 확인할 항목

iOS/Android 키보드와 큰 글씨에서 입력/다음/저장 버튼 스크롤, 앱 강제 종료 후 작성 중 복원, 자정 직전 시작한 기록의 다음 날 저장, 이전 설치 데이터의 첫 가져오기, OS 뒤로가기/제스처, 저장소 용량 부족 상황은 실제 기기에서도 확인한다. 브라우저 검증에는 가상 기록을 사용한다.
