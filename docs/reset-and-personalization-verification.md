# 초기화와 설문 흐름 변경 검증

2026-11-04

## 저장소 범위

사용자 데이터는 AsyncStorage의 `care-diary:` 네임스페이스를 사용한다. 초기화는 해당 접두사의 현재 키, 이전 버전 키, 백업 키를 열거해 삭제한다. 전체 저장소 clear는 사용하지 않는다.

- `onboarding-completed:v1`
- `demo-survey:v1`, `demo-survey-draft:v1`
- `guidance:v1`의 방문 일정, 설문 화면 위치와 최초 안내 표시
- `preparation:v1`의 단계별 체크리스트, 메모, 설문 상태와 질문 열람 위치
- `care-records:v1`의 이전 기록과 초안
- `situation-records:v2`의 직접 기록, 문답 기록, 초안, 이관 원본과 삭제 표식
- `notifications:v1`의 알림 설정, 예약 의도와 제안 표시
- 같은 네임스페이스의 복원용 사본과 사용자 화면 상태

현재 코드에서 별도로 생성하는 사용자 파일, SQLite, SecureStore, 서버 저장소는 발견되지 않았다. 공식 콘텐츠와 질문 템플릿은 코드와 번들 자산이므로 초기화 대상이 아니다.

## 복원 방지

초기화 요청 시 저장 세대를 변경하고 이전 화면 트리를 내린다. 이전 세대의 저장 함수와 진행 중인 저장은 차단하고, 이미 시작된 작업을 정리한 뒤 삭제한다. 기록 저장과 알림 예약도 같은 차단 경로를 거친다. `reset-pending:v1`을 삭제 전 저장하고 알림과 데이터 정리가 모두 끝난 뒤에만 제거한다. 중단되면 다음 실행에서 초기화를 마무리한다. 실패 시 첫 실행으로 이동하지 않고 재시도 화면을 유지한다.

알림은 이 앱의 소유 표시 또는 예약 ID로 구분해 예약 취소와 표시된 알림 제거를 수행한다. 시스템 알림 권한은 변경하거나 재요청하지 않는다. 앱 알림 설정의 초기값은 꺼짐이다.

## 설문

현재 설문은 짧은 설명이 포함된 질문만 표시한다. 별도의 lead, help, 기록 소개와 완료 안내 화면을 거치지 않고 마지막 답변을 저장한 뒤 홈으로 이동한다. 이전 버전 설문의 저장 위치는 질문 위치로 연결하며 답변과 체크리스트 원본은 보존한다.

직접 체크한 상태는 `source: manual`, 새 설문 답변에서 반영한 상태는 `source: survey`로 구분한다. 설문 변경은 자동 반영 상태를 갱신하며 수동 상태와 메모는 보존한다. 출처가 없는 이전 버전 상태는 수동 확인 기록으로 보수적으로 취급한다. 준비 여부를 현재 단계만으로 추측해 완료하지 않는다.

방문 날짜 저장 후에는 추가 안내 없이 홈으로 이동한다. 저장하지 않고 뒤로가면 날짜 질문으로 돌아오며 달력을 다시 열 수 있다.

## 검증 방법과 한계

단위 및 저장소 통합 검사는 가상의 Map 저장소와 모의 알림 API만 사용한다. 삭제 실패와 부분 실패, 앱 재시작 후 복구, 지연 저장 차단, 다른 저장 키 보존, 기록 수정과 삭제의 날짜 및 기간 조회 반영을 검사한다.

브라우저는 기존 데이터가 있는 localhost 주소를 변경하지 않고 `qa-reset-20261104.localhost:8083`이라는 별도 출처에서 생성한 테스트 데이터만 사용했다. 확인창 취소와 취소 기본 초점, 날짜 선택 후 뒤로가기와 달력 재진입, 질문의 이전 버튼과 기록 연결 제거, 초기화 후 첫 실행 복귀, 브라우저 뒤로가기 차단과 새로고침 후 초기 상태 유지, 설문에서 안내 화면 없이 홈으로 이동과 체크리스트 반영을 확인했다.

실제 iOS와 Android에서 강제 종료 직전 저장, 알림의 앱 종료 상태 수신, 시스템 절전의 영향, 알림센터 정리, 글자 확대와 시스템 뒤로가기 제스처는 기기 확인이 필요하다. 모의 API 검사만으로 실제 알림 수신을 검증했다고 취급하지 않는다.
