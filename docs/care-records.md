# 돌봄 기록 데이터·문답 계약

2026-11-02 가입 없는 시작·핵심 UX 개편 기준. 이전 현재/방금 전용 제한은 취소됐다. 기획은 PROJECT_BRIEF.md, 실제 결과는 PROGRESS.md를 우선한다.

## 날짜·시간

- 새 기록은 timingVersion:3. targetDate는 시작 시 기기 현지 오늘, kind는 daily 또는 addition이다. 날짜 직접 입력·과거 날짜 새 작성 UI는 없다.
- 자정을 넘어도 targetDate는 유지하고 캘린더는 이 날짜에 연결한다. createdAt/Answer.enteredAt/modifiedAt/Final.confirmedAt은 실제 입력·수정·확정 시각이다. 사건 발생 검증값이 아니다.
- 최초 enteredAt/localDate/timezoneOffset은 변경하지 않는다. 이전 형식에 없는 최초 시각/시간대는 추정 복원하지 않는다.
- 기존 timingVersion:2 확정 기록은 답변별 현지 날짜 조회를 유지한다. 이전 무버전 확정 기록은 원래 선택 날짜를 유지한다.

## 질문과 상태

- daily 저장 구조는 기본 5항목 + notes를 유지한다. 현재 개발용 문답은 식사 → 이동 → notes로 짧게 진행하고 나머지는 unanswered로 남긴다. 모든 항목을 완주하게 하지 않는다. addition은 additional 한 항목이다. 각 항목은 고유 답변 ID를 가진다.
- answered/unobserved/skipped/unanswered/none을 구분한다. none은 notes에서 사용자가 없어요를 선택한 경우에만 가능하다.
- 아침/점심/아까 등 하루 안의 회고 표현을 차단하지 않는다. 보내기 또는 선택으로 진행하며 이미 답한 기본 항목을 다시 요구하지 않는다.
- 중간 마무리와 기본 종료는 notes로 이동한다. 즉시 뒤로가기·임시 저장은 notes를 강제하지 않는다.
- 문답·항목별 확인 체크 없이 최종 초안에서 한 번 확정한다. Final.content.reviewed는 이 최종 확정을 나타내는 보존 필드다.

## 원문·초안·확정

- 원문 Source, 자동 Draft.summary, 사용자 수정 review/Final.content를 구분한다. 원문 수정은 revision을 올리고 activeDraftId/review를 무효화한다.
- mock 요약은 answered 원문을 그대로 배치한다. 그 외 text=null이며 상태 라벨은 구분해서 보인다. 미답변에 정상·도움 없음·특이사항 없음을 생성하지 않는다.
- 항목/형식/근거 ID/원문 전체 일치를 검증한다. ID만으로 사실성을 보증하지 않으며 추측·부정 반전·빈도 확대를 거부한다. 상충·불확실 표현을 그대로 유지해 사용자에게 확인시킨다.
- 같은 초안 확정 ID를 고정해 재시도 시 첫 확정 결과/시각을 유지한다. 이미 확정된 원문/최종 이력은 덮어쓰지 않는다. 오탈자 정정은 별도 이력으로 보존한다.

## 추가 기록·중복 방지

- 오늘 대상의 확정 기록에서만 새 추가 기록을 시작한다. parentId로 원래 기록을 연결하고 별도 ID·원문·초안·확정을 가진다.
- 저장소 트랜잭션에서 같은 부모/오늘의 미확정 추가 기록을 재사용한다. 추가 기록 화면에서 재진입해도 같은 원본 묶음의 미확정 기록을 재사용한다.
- 확정된 추가 기록은 보존하고 사용자가 의도적으로 다음 추가를 시작하면 새 기록을 만든다. 내용이 같은 서로 다른 사건을 의미 분석해 자동 병합하는 기능은 없다.

## 저장 호환

- key=care-diary:care-records:v1, 봉투 version:1 유지. 현재 6항목/추가 1항목과 구형 5항목을 검증한다.
- 이전 확정 데이터는 읽기만으로 변경하지 않는다. 이전 미확정 데이터는 이어쓰기를 선택하면 migrateDailyRecord로 v3 변환하고 migration에 원래 source/review/phase를 보존한다.
- 기존 초안·최초 시각·대상 날짜는 보존하며 특이사항 미답변을 추가하고 새 최종 확인을 요구한다. 중단 시 다시 저장된 상태로 이어 쓴다.
- 읽기 실패·손상 데이터는 빈 자료로 취급해 덮어쓰지 않는다. 쓰기를 직렬화해 중복 추가와 동시 저장의 유실을 줄인다.

## 공통 이동·연결 상태

- 기존 AppHeader/useSafeExit/createExitGate/task-scope를 유지한다. 저장 후 이동, 실패 시 계속 작성/저장하지 않고 나가기, 오래된 결과 무시가 같은 경계를 사용한다.
- 실제 AI·음성 API는 없다. 실제 호출은 이후 서비스 소유 서버를 거치고 키는 서버 비밀 설정에만 둔다. 현재 외부 전송·민감한 답변 로그는 없다.
- AsyncStorage에 앱 자체 암호화·계정별 분리·백업은 없다. OS 강제 종료·웹 탭 종료 직전 비동기 저장 완료를 보장하지 않는다. 실제 민감정보 운영 전 보호 설계가 필요하며 개발에는 가상 답변을 쓴다.

## 최신 UX 저장 계약

- 시작 키 care-diary:onboarding-completed:v1, 단계 키 care-diary:demo-survey:v1는 유지한다. demo 접두사는 호환용이며 체험/로그인 상태를 뜻하지 않는다. 소개와 단계 저장을 읽기 전 라우팅하지 않는다.
- care-diary:guidance:v1는 단계별 안내 seen, 신청 경험, visit(date/time), visitSetupDone, 미완성 visitInput, 방문 미완료 확인 visitChecked를 별도 저장한다. 최초 업그레이드에서는 기존 단계만 seen 처리해 재안내를 강제하지 않는다. 기록 데이터는 수정하지 않는다.
- 일정 계산은 현지 연월일 차이, 일지 대상 날짜와 일정 날짜 입력은 별개다. 일정의 날짜/시간은 사용자가 적는 메모이며 공식 일정/서버 시각이 아니다.
- 모의 제어 표현은 mock-intent.ts에 명시된 정확 문장만 인식한다. 제어 상태와 원문 rawText를 함께 저장한다. 자유 답변 수정 시 이전 제어 원문은 현재 필드에서 제거하고 관련 초안을 재생성한다.
- 최종 저장은 putRecord 성공을 기다린 뒤 현재 편집 상태를 닫고 recordDate의 캘린더/완료 상태/방금 저장한 내용으로 바꾼다. 저장 전 편집을 별도 경로에 남기지 않는다. 실패는 초안을 유지한다. 추가 기록은 부모별 미확정 기록 재사용으로 중복 생성을 막는다.
- 문답 더보기의 직접 건너뛰기/정리/이력 보기와 뒤로가기 임시 저장은 AI 연결 없이 작동한다. 삭제는 목록의 해당 초안 더보기에서 확인한다.

## 최신 조회·표시 계약 (2026-11-02)

- 데이터 마이그레이션 없이 UI 조회 계층만 분리했다. confirmedOnDate는 마지막 확정 source 날짜만 이용하고 새로 저장한 ID를 우선 표시한다. 다른 확정 일지도 모두 유지한다. pendingRecords는 미확정 문답/초안과 정정 임시 내용을 별도 /drafts에서 조회한다. 필터·정렬은 원본 배열/레코드를 변경하지 않는다.
- 캘린더의 완료/작성 중 표시는 기존 저장 결과에서 계산한다. 작성 중 상태 표시는 유지하되 초안 내용/이어서 작성하기 목록은 본문에 펼치지 않는다. 빈 날짜에 대시나 정상 상태를 만들지 않는다.
- /records?draft=ID는 기존 레코드를 검증해 재개한다. 원래 대상 날짜/첫 입력 시각을 유지하며, 존재하지 않는 ID는 새 기록으로 대체하지 않는다. 오탈자 정정 중이면 해당 편집으로 돌아간다. 과거 초안 이어쓰기는 기존 대화 재개이며 과거 날짜 새 생성이 아니다.
- 일지 확인의 읽기/편집 전환은 review 내용만 갱신한다. 원문과 모의 초안은 유지한다. 최종 저장 성공 전까지 finals를 확정 표시하지 않고, 실패 시 입력을 그대로 남긴다.
- 날짜 전용 문자열은 UTC Date로 변환하지 않고 연·월·일을 직접 표시한다. timestamp는 기기 현지 시각으로 표현하며 초 단위는 UI에서만 생략한다. 저장된 ISO 값은 그대로 유지한다. 일정 날짜는 계속 YYYY-MM-DD, 시간은 HH:mm/null이다.
