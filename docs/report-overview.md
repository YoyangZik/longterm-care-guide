# 종합 보고서 구성과 출력 동작 (2026-11-04)

현재의 세부 응답 보정과 근거 검증 정책은 `docs/report-validation.md`를 참고한다. 요청 때만 짧은 ID를 쓰고 서버에서 원래 ID로 복원하며 기존 저장 구조는 유지한다.

## 합의한 보고서

개별 일지나 유형별 요약 목록을 만드는 대신, 선택 기간의 모든 원문으로 피보호자의 생활 수행과 실제 도움을 종합한다.

1. 기본 정보: 기간, 분석한 기록 수, 생성일. 기존 앱 메타데이터를 사용한다.
2. 전체 돌봄 모습: 기록이 충분하면 연결된 2~3개 문단으로 독립 수행, 도움이 필요했던 상황과 실제 도움을 종합한다.
3. 주요 돌봄 양상: 중요한 양상 2~4개를 짧은 문단으로 설명한다. 유형을 모두 채우거나 단발 사건을 반복으로 만들지 않는다.
4. 확인 범위와 근거: 자료의 한계와 기록 공백을 설명하고, 본문 뒤에서 근거 날짜와 원문을 확인한다.

기간 중 변화를 별도 항목으로 만들지 않는다. 짧은 기록의 차이를 호전, 악화나 돌봄 필요 감소로 해석하지 않는다. 독립 수행과 도움을 받은 사실을 모두 보존하고, 시간 추세 대신 각각의 상황을 설명한다. 보호자에게 유리하거나 불리하도록 사실을 선택하지 않는다. 진단과 등급 예측은 하지 않는다.

## 구현

- 서버 `workers/src/protocol.js`의 `REPORT_INSTRUCTION`을 위 종합 서술형 지침으로 변경했다. 기존 `sections`, `text`, `recordIds`, `repeated` 형식을 유지한다. 근거 ID 검사는 유지하고 제목의 정확한 일치만으로 결과를 거부하지 않는다.
- 앱 `report-content.tsx`는 본문을 먼저 표시한다. 근거 기록은 뒤쪽 한 곳에 모으고 기본적으로 접어둔다. 펼치면 각 본문의 근거 날짜, 현재 원문 상세 링크와 생성 당시 원문을 확인할 수 있다. 같은 원문을 본문마다 반복 출력하지 않는다.
- PDF `report-html.ts`도 종합 본문을 먼저 배치하고 근거 목록과 원문은 뒤에 둔다. PDF의 근거 목록에는 해당 원문으로 이동하는 내부 앵커를 연결했다. HTML 이스케이프와 공식 판정 자료가 아니라는 기존 고지를 유지한다.

## 재생성 제거와 API 사용

보고서 상세에서 같은 기간 다시 생성 버튼을 제거했다. 기간 선택 화면에서도 같은 시작일과 종료일의 저장된 보고서가 있으면 저장본 열기로 바뀐다. `generateReport()` 자체도 동일 기간 저장본을 먼저 반환해 API 재호출을 막는다. AI 동의가 철회되어도 저장본 열기와 PDF 출력은 가능하다.

같은 기간의 기록을 수정하거나 삭제해도 저장본을 다시 만들지 않는다. 생성 후 기록이 변경됐다는 안내와 생성 시점, 생성 당시 근거를 유지한다. 날짜가 바뀌거나 다른 기간을 선택해 아직 저장되지 않은 날짜 범위가 되면 새 보고서를 생성할 수 있다. 이는 기기 내 중복 호출 방지이며 배포 서비스의 요금제별 서버 제한을 새로 구현한 것은 아니다. 기존 Workers 호출 제한은 유지한다.

보고서 목록과 상세에는 삭제 버튼이 있다. 기간을 보여주는 확인창에서 확정하면 해당 보고서만 삭제하며 원본 기록, AI 한 줄 요약, 다른 보고서와 기존 PDF 파일은 유지한다. 삭제는 AI를 호출하지 않는다. 저장 쓰기에 실패하면 보고서를 유지하고 재시도를 안내한다. 같은 기간의 보고서를 모두 삭제한 후 사용자가 새로 만들기를 선택하면 별도 AI 요청이 발생한다.

이미 저장된 보고서의 본문은 재작성하지 않는다. 따라서 옛 보고서의 항목식 본문은 그대로이며, 새 종합 서술형 지침은 Worker 배포 후 아직 저장본이 없는 기간의 새 보고서부터 적용된다. 기존 자료 삭제나 마이그레이션은 하지 않는다.

## Printing did not complete 원인

설치된 SDK 58 `expo-print`의 `ios/ExpoPrintWithPrinter.swift`에서 완료 콜백에 프린터 오류가 없지만 `completed == false`이면 `PrintIncompleteException`을 반환한다. 해당 예외 문구가 `Printing did not complete`다. 실제 인쇄 없이 인쇄창을 닫거나 취소했을 때도 발생하며, 앱은 이를 영어 그대로 표시하고 있었다. 문서상 iOS는 인쇄를 시작하기 전에 창을 닫으면 Promise를 거부하지만 Android는 창을 보여준 시점에 해결되어 취소를 같은 방식으로 알 수 없다.

`report-pdf.ts`에서 iOS의 `ERR_PRINT_INCOMPLETE` 또는 해당 정확한 메시지만 취소로 구분해 "인쇄를 취소했어요. 저장된 보고서는 그대로예요."라고 안내한다. 실제 프린터 오류는 별도의 한국어 오류로 표시하며 인쇄 성공으로 취급하지 않는다. Android에서는 인쇄 화면을 열었다고만 안내하고 실제 출력 완료를 단정하지 않는다. 어떤 경우에도 저장된 보고서를 삭제하거나 AI를 호출하지 않는다.

참고: [Expo SDK 58 Print 문서](https://docs.expo.dev/versions/v58.0.0/sdk/print/).

## 검증 및 반영

가상 기록과 모의 네이티브 API로 다음을 검사했다.

- 동일 기간 재요청 시 Claude 호출이 한 번으로 유지되고, 기록 삭제 및 동의 철회 후에도 원래 저장본을 반환한다.
- PDF에서 모든 종합 본문이 근거 목록보다 앞에 있고 원문 링크와 HTML 이스케이프가 유지된다.
- 기존 보고서도 읽을 수 있고 근거 ID 오류와 단일 기록의 반복 표시는 계속 거부한다.
- iOS 인쇄창 취소는 중립 안내, 프린터 연결 오류는 오류로 구분한다. 보고서 객체가 바뀌지 않으며 AI 호출은 0회다.
- 기존 공유, 파일 복사 완료 후 공유 및 저장, 캐시 정리 테스트를 유지한다.

실제 Claude에서 새 보고서가 생성된 결과나 iPhone/AirPrint 프린터, Android 인쇄 서비스 및 PDF 페이지의 시각 검수는 이번 환경에서 직접 검증하지 못했다. 모의 테스트를 실제 기기 검증으로 간주하지 않는다.

Worker 프롬프트 변경으로 **Cloudflare Workers 재배포가 필요하다**. 앱은 새로고침/업데이트한다. 이번 작업에서 실제 배포는 하지 않았다.
