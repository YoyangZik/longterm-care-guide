# UI/UX 개선 적용 결과

## 적용 기준

합의한 기존 색상과 큰 글씨를 유지하고, 공통 스타일을 일괄 덮어쓰지 않았어요. 홈과 보고서 화면을 먼저 수정한 뒤 홈의 실제 렌더링과 보고서의 상태 테스트를 확인하고, 역할별 보조 스타일을 다른 화면에 적용했어요. 새 패키지와 네이티브 설정 변경은 없어요.

## 변경 사항

- 홈: 단계 변경을 제목 위로 분리하고 옅은 배경 버튼으로 표시해요. 방문 일정은 날짜 중심의 흰색 카드, 남은 기간은 짧은 보조 문장으로 정리했어요. 질문 안내는 체크리스트와 분리한 이동 카드로 표시해요.
- 체크리스트: 번호를 제거하고 아이콘과 짧은 상태를 사용해요. 카드 전체가 상세 이동이며 상태 문구는 버튼이 아니에요. 좁은 화면에서 상태가 자연스럽게 다음 줄로 넘어갈 수 있어요.
- 일반 준비 항목: 선택지는 ‘준비했어요 / 아직 준비를 마치지 않았어요’로 표현해요. 확인 항목은 ‘확인했어요 / 아직 확인하지 않았어요’를 사용해요. 소견서의 별도 제출 상태와 기존 해당 없음 처리는 보존했어요.
- 저장: 체크리스트는 명시적 저장을 해야 반영돼요. 미저장 변경 후 뒤로가면 계속 수정/저장하지 않고 나가기를 선택해요. 기존 기록 수정에도 확인을 추가했어요. 새 기록 자동 초안 저장은 그대로예요.
- 방문 질문: 뒤로는 직전 질문, 첫 질문에서는 소개로 이동해요. 나가기는 별도 보조 버튼이고 마지막 저장 위치와 완료 이력을 유지해요. 완료 후 홈 재진입만으로 위치를 초기화하지 않아요. 위치 저장 실패는 별도 안내해요.
- 질문 기록: 단일/복수 선택 도형을 구분하고 선택 상태를 체크로 보여줘요. 직접 적기/덧붙이기/불확실성 펼치기는 옅은 배경 보조 영역으로 표시해요. 웹 접근성 선택값도 명시했어요.
- 직접 입력: 유형별 예문을 제공하고 본문 9,000자부터 10,000자 한도를 표시해요. 질문 입력/추가 설명은 3,600자부터 4,000자 한도를 표시해요. 한도 도달 시 붙여넣은 내용을 확인하도록 안내하고 입력 제한 자체는 유지해요.
- 기록 조회: 기간 버튼을 알아보기 쉽게 하고, 날짜/유형과 본문 위계를 정리했어요. 카드의 중복 ‘자세히 보기’ 대신 이동 화살표를 사용해요. 접근성 이름에는 시간과 짧은 미리보기를 포함해요. 120자 제한은 음성 읽기용 이름에만 해당하며 원문/AI 결과는 자르지 않아요.
- 보고서: 섹션마다 반복하던 카드 경계를 없애 문단을 읽는 데 집중하도록 했어요. PDF 공유/인쇄/저장을 본문 뒤에 묶고, 목록 이동과 삭제를 분리했어요. 목록 복귀/기간 변경 시 완료 안내를 해제해요. 생성 중 기간 선택 제한과 저장된 보고서 재사용은 유지해요.
- PDF: 저장/공유 파일명에 보고서 기간과 생성 시각을 쓰고 내부 ID를 제외해요. 같은 이름은 숫자 접미사로 구분하고 덮어쓰지 않아요. 내부 URI를 완료 문구에서 제거했어요. iOS 앱 내부 사본과 공유창의 외부 저장을 구별하며, 폴더 선택/내보내기 취소는 취소로 안내해요.
- 설정: 앱 안내/개인정보/개발자 메뉴의 터치 영역을 흰색과 얇은 경계로 표시해요. 초기화는 옅은 위험색 영역으로 구별해요. AI 설정 위치, 등록 완료 시 두 관리 버튼, 동의 범위는 유지해요.
- 소견서: 상태 수정/기한 수정/미정 선택을 알아보기 쉬운 보조 버튼으로 표시해요. 상태 구분과 실제 저장값은 바꾸지 않았어요.
- FAQ: 펼침 목록을 그룹으로 묶고 어절 줄바꿈을 개선했어요. 공식 링크/개인정보 링크는 보조 영역으로 구별하고 문서 내용은 보존했어요.
- 날짜/시간: 방문 날짜의 중복 여백을 줄였어요. 시간휠의 웹 초기 스크롤 위치를 동기화하고 선택 시간을 별도 문구로 보여줘요. 네이티브 초기 스크롤 동작은 유지했어요.
- 설문/안내/질문/헤더/팝업: 실제 사용하는 텍스트 컴포넌트에 한글 줄바꿈 정책을 적용했어요. 전역 타이포그래피 토큰은 변경하지 않았어요.
- AI 오류: 응답 구조 실패의 개발자 설명을 쉬운 결과/문의 안내로 바꿨어요. 인증, 동의, 실제 근거 검증과 Worker 프로토콜은 그대로예요.

## 합의와 연결해 보고할 사항

1. **기존 unknown 이력:** 기존 저장 형식에서 ‘명시적 모름’과 일부 오래된 이력을 항상 확실히 구분할 수는 없어요. 데이터가 아예 없는 경우만 ‘선택 전’, todo는 ‘아직이에요’, 기존 unknown은 ‘확인 필요’로 보수적으로 표시해요. 임의 마이그레이션이나 답변 추정은 하지 않았어요.
2. **웹 접근성:** 기존 질문 선택지와 보고서 기간의 웹 접근성 트리에서 선택값이 제대로 반영되지 않는 것을 확인해 `aria-checked`를 추가했어요. 보고서 90일 선택이 AX에서도 선택됨으로 표시되는 것을 확인했어요. 실기기 VoiceOver/TalkBack 검증을 대신하지는 않아요.
3. **시간 선택기:** 웹에서 중앙 선택 띠/선택 문구/적용 시간이 오전2:00으로 일치함을 확인했어요. iPhone/Android의 휠 동작을 직접 확인하지 못했으므로 네이티브 초기 스크롤 방식은 바꾸지 않았어요.
4. **보고서 상세 실화면:** 이 환경에는 동의/코드가 등록된 저장 보고서가 없어 실제 AI를 호출해 결과 화면을 만들지 않았어요. 상세 상태와 목록 복귀는 가상 보고서 UI 테스트로 확인했고, 본문 전체의 최종 미감과 실제 PDF 페이지 나눔은 저장 보고서가 있는 실기기에서 확인해야 해요.

## 검증 결과

- `npm.cmd run lint`, `npx.cmd tsc --noEmit` 모두 통과했어요. 린트 경고도 없어요.
- 기존 테스트와 새 회귀 검사 포함 **198개 통과, 실패 0개**예요. 로그: [tests.txt](tests.txt).
- 새 검사는 상태 의미/데이터 불변, 저장 전 미반영, 저장 실패 시 선택 유지, 질문 이전 이동/나가기/완료 이력, 보고서 완료 안내 수명, 기록 수정 취소/원본 보존, PDF 파일명 충돌/취소/덮어쓰기 방지를 포함해요.
- 웹 실제 확인: 체크리스트 취소 후 기존 값 유지, 방문 질문2→1 및 나가기, 홈320/390/430px, 설정 메뉴, 질문 복수 선택, 기록 목록, 90일 기간 선택과 동의 전 생성 차단, 달력과 시간 선택기.
- 모든 조작은 별도 localhost:8094 가상 자료 환경에서 수행했어요. 실제 돌봄기록, 개인정보, 접근 코드, 유료 AI 요청은 사용하지 않았어요. 기존 휴대폰용 8081 서버를 종료하지 않았어요.
- 미검증: iOS/Android 실제 키보드와 제스처, 글자 확대와 스크린리더, 네이티브 시간휠, 실제 PDF 공유/파일 저장/프린터 출력, 모든 화면의 전체 기종 조합.
- 실제 개선 화면 13장을 이 폴더에 저장했어요. 감사용 8094 서버는 종료했고 임시 브라우저 화면 크기도 복원했어요.
