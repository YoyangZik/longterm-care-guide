# 장기요양길잡이 출시 전 UI/UX 감사

감사일: 2026-11-05. 대상: 현재 작업 트리의 Expo 58 앱. 코드 수정 없이 조사했어요.

## A. 전체 평가

**확인한 P0는 없으며, P1 1건, P2 12건, P3 1건을 정리했어요.** 출시 승인 판정은 아니에요. iPhone과 Android에서 키보드, 스크린리더, 알림, 실제 PDF 출력은 아직 확인하지 못했어요. 그 미확인 항목을 확인된 결함으로 계산하지 않았어요.

| 항목 | 점수 / 10 | 판단 근거 |
|---|---:|---|
| 시각적 완성도 | 7 | 차분한 색, 큰 본문, 카드 위계는 좋아요. 390px 홈 제목과 질문의 어절 분리, 체크리스트 번호 역전이 완성도를 낮춰요. |
| 디자인 일관성 | 6.5 | 공통 토큰과 버튼 규격이 있어요. 한글 줄바꿈 적용, 단일 선택과 복수 선택 모양, 뒤로가기의 저장 의미가 달라요. |
| 사용 편의성 | 6.5 | 두 기록 방식과 기간 필터, 페이지 이동은 명확해요. 방문조사 질문에서 이전 질문으로 돌아갈 수 없어요. |
| 정보 전달력 | 7 | 원문과 AI 결과가 구분되고 비활성 이유가 표시돼요. 유사한 상태 변경 버튼과 일부 기술적인 오류 설명은 어려워요. |
| 접근성 | 6 | 본문 18px, 기본 버튼 높이 58, 주요 대비는 양호해요. 달력 폭과 기록 카드 접근성 이름은 개선 여지가 있고, 실기기 확대 및 음성 읽기는 미확인이에요. |

| 출시 준비도 | 5.5 | 핵심 웹 여정과 191개 자동 검사는 통과했지만, 아래 P1과 모바일 전용 핵심 여정 확인이 남았어요. |

점수는 동일 기준으로 개선 전후를 비교하기 위한 정성 평가예요. 모든 기종의 정상 동작을 의미하지 않아요.

### 실제 확인 환경과 제한

- localhost:8094의 별도 브라우저 저장소에서 가상 자료만 사용했어요. 기존 휴대폰용 8081 서버와 실제 사용자 저장소는 건드리지 않았어요.
- 기본 390 × 844 CSS 화면에서 여정을 수행했어요. 홈은 320 × 568, 430 × 932에서도 확인했고 DOM의 실제 viewport 크기를 대조했어요. 브라우저 크기는 실제 iPhone 기종이나 시스템 글자 확대의 대체 검증이 아니에요.
- [스크린샷 폴더](screenshots/)에 37장을 저장했어요. 개발 서버의 Bundling 화면과 오류 오버레이는 제품 UI 평가에서 제외했어요.
- 실제 Claude 호출, 접근 코드 입력, 외부 공유, 인쇄, 개인정보 전송은 하지 않았어요. 동의 팝업은 열어 내용을 확인하고 **동의하지 않음**으로 닫았어요.
- 직접 기록 1건, 질문 기록 1건, 개발자 메뉴의 가상 기록 90건을 이 격리 환경에 저장했어요. 90건 추가 시점에는 총 91건, 질문 기록 저장 후에는 총 92건이에요.
- 일부 주소 직접 진입에서 Metro의 `Requiring unknown module "59"` 오류가 발생했어요. 캐시 초기화 후 앱 내부 이동으로 네 단계 홈까지 확인했어요. 개발 환경 문제로 별도 기록하며, 네이티브 출시 앱에서도 발생한다고 판단하지 않았어요.
- 원본 코드에는 기존 미커밋 변경이 많았어요. 이번 감사는 앱 코드, 데이터 모델, Worker를 수정하지 않았어요. 추가한 것은 이 보고서와 화면 증거뿐이에요. 감사용 8094 서버는 종료했어요.

### 현재 기획을 유지한 항목

- 기록 안내의 ‘확인했어요’는 홈 체크리스트로 이동해요. 바로 기록 작성으로 보내지 않아요. 기록 탭의 일회성 강조와 말풍선 꼬리도 확인했어요.
- 보고서 근거 목록은 앱과 PDF에서 의도적으로 숨긴 상태예요. 내부 근거 ID와 생성 당시 원문 사본은 검증과 변경 감지에 남아 있어요. 목록이 없다는 이유로 결함 처리하지 않았어요.
- 방문조사 질문은 **답변을 입력하지 않고 떠올리는 안내**예요. 답변 작성, 답변 요약, 별도 방문 준비 PDF는 구현된 기능이 아니므로 고장으로 분류하지 않았어요. 보고서 PDF는 별도 기능이에요.
- 앱 전용 음성 입력은 현재 기록 화면에 없어요. 운영체제 키보드 받아쓰기까지 앱 구현으로 간주하지 않았어요.
- 일반 데이터 전체 백업/내보내기 메뉴는 현재 없어요. PDF 내보내기가 전체 데이터 백업은 아니에요. 백업 기능 신설은 이번 감사의 수정 권고 범위에서 제외했어요.
- AI 이용 설정을 개발자 메뉴에 두는 정책과 배포 전 호출 제한 조정은 기존 보류 결정을 유지해요.
- 사용하지 않는 이전 `features/records/records-screen.tsx`나 템플릿 `components/app-tabs.web.tsx`를 현재 화면으로 잘못 평가하지 않았어요.

## B. 문제 목록

아래 파일 위치는 감사 시점 기준이에요. 원본 코드가 바뀌면 줄 번호도 바뀔 수 있어요.

### UX-01 / P1 / 방문조사 질문에서 이전 질문을 볼 수 없어요

- **위치:** `src/features/visit-walkthrough/screen.tsx:23`, `:26`, `:43`.
- **현재:** 질문 2/16의 ‘뒤로’를 누르면 1/16이 아니라 홈으로 나가요. 다시 들어가면 2/16에서 이어져요. 질문 안에는 이전 버튼이 없어요.
- **영향:** 직전 안내를 다시 읽으려는 주요 준비 여정이 끊겨요. 초기 설문에서 정상 동작하는 뒤로가기와도 의미가 달라요.
- **권장:** 질문 중에는 직전 질문으로 이동하고, 별도의 ‘나중에 이어보기’로 홈 복귀를 제공해요. 첫 질문의 뒤로는 소개로 이동하도록 해요.
- **수정 영향:** 질문 위치 저장, 완료/재시작, 홈 이어보기. 답변 입력 기능을 새로 만들 필요는 없어요.
- **확인 방법:** 홈 → 방문조사 질문 → 시작 → 다음 → 뒤로 → 홈 → 이어서 살펴보기.
- **검증 수준:** R/C. [질문1](screenshots/06-visit-question-1.jpg), [질문2](screenshots/07-visit-question-2.jpg). iOS 스와이프와 Android Back은 M.

### UX-02 / P2 / 핵심 제목과 한글 어절이 잘려 읽혀요

- **위치:** `src/features/home/home-screen.tsx:46`, `src/features/preparation/completion-screen.tsx:36`, `src/features/faq/screen.tsx:24`, `src/features/records/situation-screen.tsx:98`, `src/components/readable-text.ts:6`.
- **현재:** 390px 방문 홈에서 ‘방문조사를 기다려 / 요’, 320px 신청 홈에서 ‘신청을 준비해 / 요’가 돼요. 질문과 FAQ도 ‘부 / 분’, ‘어 / 떡하나요’처럼 나뉘어요. ReadableText가 일부 화면에만 적용돼요.
- **영향:** 화면의 가장 중요한 현재 상태를 빠르게 읽기 어려워요. 본문 크기가 커도 읽기 경험은 나빠져요.
- **권장:** 공통 한글 줄바꿈 정책을 적용하고, 홈 제목과 단계 변경 버튼은 좁은 화면에서 행을 분리해요. 글씨를 일괄 줄이는 방식은 피하고 긴 문구만 별도 문장 단위로 조정해요.
- **수정 영향:** 제목/질문/FAQ/팝업 공통 텍스트와 홈 헤더 배치.
- **확인 방법:** 390px 방문 홈, 320px 신청 홈, 질문 2/3, FAQ 목록 확인.
- **검증 수준:** R/C, 네이티브 줄바꿈 M. [방문 홈](screenshots/05-home-visit.jpg), [작은 홈](screenshots/36-home-small.jpg), [질문](screenshots/26-question-multiple.jpg).

### UX-03 / P2 / 체크리스트 번호가 화면 순서와 달라요

- **위치:** `src/features/preparation/checklist.tsx:33`, `:37`.
- **현재:** 확인할 내용과 준비할 일을 나누어 보여주면서 번호는 원래 배열 순서를 사용해요. 방문 홈은 1, 2, 5 뒤에 3, 4가 오고, 신청 전 홈은 1, 2, 4 뒤에 3이 와요.
- **영향:** 빠진 항목이 있거나 잘못 진행했다고 느낄 수 있어요.
- **권장:** 번호가 절차를 뜻하지 않는다면 아이콘으로 바꾸거나, 실제 표시 순서대로 번호를 부여해요. 섹션별 번호를 새로 시작하는 선택도 가능해요.
- **수정 영향:** 단계별 체크리스트 표시만 해당해요. 저장 키는 유지해요.
- **확인 방법:** 방문 홈과 신청 전 홈을 위에서 아래로 읽어요.
- **검증 수준:** R/C. [방문 홈](screenshots/05-home-visit.jpg), [신청 홈](screenshots/35-home-before-application.jpg).

### UX-04 / P2 / ‘변경 저장’이 있는데 뒤로만 눌러도 저장돼요

- **간격:** 페이지 24, 카드 20, 항목 사이 12~16, 섹션 사이 24~32로 현재 토큰에 맞춰 정리해요. 7/30/90 기간은 현재처럼 왼쪽 정렬과 간격 10을 유지해요.
- **선택:** 단일은 원형, 복수는 사각 체크 표시로 구분해요. 색상 외에 체크/윤곽/선택 상태 텍스트를 함께 사용해요.
- **버튼:** 기본 CTA 높이 58, 일반 터치 영역 48을 유지해요. 위험 행동은 별도 확인과 명확한 취소를 제공해요. 초기화 모달처럼 취소를 우선시하는 현재 방식은 좋아요.
- **저장과 뒤로:** 새 기록의 자동 초안 보존과 기존 기록 수정의 확정 저장을 명시적으로 구분해요. ‘저장’ 버튼이 있는 화면의 뒤로 동작을 공통 규칙으로 정하고, 저장 실패 시 화면 이탈을 막는 기존 보호는 유지해요.
- **상태 문구:** 진행, 성공, 실패 안내는 해당 작업에 묶어요. 다른 기간/다른 보고서로 옮기면 이전 완료 안내를 해제해요. 숫자 퍼센트로 AI 진행률을 꾸며내지 않아요.
- **AI와 원문:** AI 제목, 기간, 포함 건수, 생성일, 참고자료 안내를 유지해요. 원문을 AI 내용처럼 꾸미거나, 실패 대체 미리보기를 생성 성공처럼 표시하지 않아요.
- **오류:** 첫 문장은 사용자가 이해할 결과, 다음 문장은 보존 여부와 할 행동으로 작성해요. 내부 ID나 서버 응답을 그대로 노출하지 않고 문의에 필요한 코드만 별도로 보여줘요.
- **접근성:** 명시적인 버튼 이름에 식별 가능한 요약을 포함하고 선택/비활성/펼침 상태를 함께 제공해요. 모달 진입/닫기 때 초점 이동과 배경 읽기 차단을 실제 스크린리더로 확인해요.

기본 토큰의 불투명 색상을 수식으로 계산한 대비는 ink/background **11.48:1**, muted/white **5.68:1**, green/white **6.74:1**, muted/pale **4.92:1**이에요. 이 조합은 요청한 일반 글자 4.5:1 기준을 넘어요. 모든 임의 색상, 투명도와 OS 상태까지 통과했다는 뜻은 아니에요. 비활성 버튼의 옅은 색을 그 자체로 활성 텍스트 대비 위반이라고 계산하지 않았어요.

## 보고서와 PDF 별도 평가

- 앱 결과 화면과 PDF 모두 기간, 건수, 생성일, AI 참고 안내를 구분해요. 보고서 본문은 섹션과 문단으로 보여줘요. 새 지침은 개별 기록 나열이 아닌 전체 돌봄 상황 서술을 요구해요. 실제 모델의 결과 품질을 이번 감사에서 새로 생성해 평가하지는 않았어요.
- 앱의 `reportParagraphs`를 PDF HTML에서도 사용하므로 문단 구분 기준은 같아요. HTML 삽입 시 `escapeHTML`을 적용해요.
- PDF HTML에는 A4 여백, 제목 뒤 분리 방지, 문단 orphans/widows 설정과 한글 시스템 폰트 후보가 있어요. **실제 PDF 파일을 생성/렌더링하거나 종이 인쇄하지 않았으므로 한글과 페이지 나눔 정상 판정은 보류해요.**
- 근거 목록 제거는 기존 합의대로 유지돼요. 본문의 근거 ID 노출은 확인되지 않았어요. 파일명의 내부 ID는 UX-09로 별도 정리했어요.
- 저장 보고서 읽기와 PDF 변환은 AI 요청 경로를 사용하지 않아요. 기존 테스트에서 재호출이 없음을 확인했어요. 이전 보고서는 자동 재작성되지 않으며 생성 후 원문 변화 안내만 표시해요.
- iOS의 인쇄창 취소는 `Printing did not complete`를 그대로 오류 표시하지 않도록 처리돼 있고 해당 모킹 테스트도 통과했어요. 실제 프린터 오류와 취소의 구분은 실기기에서 다시 확인해야 해요.

## E. 실제 iPhone 사용자 테스트 체크리스트

모든 조작은 가상 기록과 별도 테스트 설치에서 진행해요. 각 항목은 화면 녹화 또는 전후 캡처와 OS/기종을 남겨요. Android에서도 같은 절차를 수행하되 ‘파일 앱/공유창/스와이프’를 해당 OS 동작으로 바꿔요.

1. **최초 실행:** 새 테스트 설치 → 네 단계 중 하나 선택 → 개인화 진행 → 완료 안내 → 돌봄기록 안내의 확인했어요. 홈 체크리스트가 열리고 기록 탭 강조는 한 번만 나타나는지 확인해요. 앱 재실행 후 안내가 반복되지 않아야 해요.
2. **설문 뒤로:** 신청 전/재신청/소견서 준비 중 기한/결과 모름 분기를 각각 진행해요. 질문마다 뒤로를 한 번씩 눌러 직전 질문과 선택을 확인하고, 답을 바꿔 이후 분기도 맞는지 확인해요. 첫 질문까지 갔을 때 중간 홈으로 빠지면 실패예요. 헤더 뒤로, iOS 스와이프, Android Back을 구분해요.
3. **방문 질문:** 질문1→2→뒤로→재진입을 수행해 UX-01 재현 여부를 기록해요. 수정 후에는 1로 복귀해야 해요. 완료/이어보기 위치도 확인해요.
4. **글자 확대:** iPhone 손쉬운 사용의 큰 텍스트를 기본/중간/최대로 바꿔 홈, 긴 질문, 체크리스트, 동의 모달, 초기화 확인을 열어요. 문구/버튼 겹침과 하단 접근 가능 여부를 확인해요. 작은 기기와 큰 기기를 함께 사용해요.
5. **접근 코드 키보드:** 동의 완료 후 가상 테스트용 유효 코드 64자를 붙여넣어요. 완료 키, 빈 공간 터치, 스크롤 각각으로 키보드가 내려가는지 확인해요. 키보드가 떠 있어도 등록 버튼에 닿아야 해요. 잘못된 형식/거절/유효 코드의 피드백과 재실행 후 보안 저장 복원도 확인해요. 코드는 촬영하지 않아요.
6. **AI 끔:** 동의하지 않은 상태와 동의 철회 상태에서 직접/질문 기록을 각각 저장해요. 원본이 남고 요약은 차단돼야 해요. 테스트 서버의 본문 없는 요청 카운터로 새 AI 요청 0건을 대조해요. 단순히 비활성 버튼만 보고 비전송이라고 결론 내리지 않아요.
7. **초안과 편집:** 질문 중 직접 입력→뒤로→초안 이어쓰기→앱 강제 종료→재실행. 입력과 위치가 보존되는지 확인해요. 저장 기록 수정 중 뒤로/스와이프의 의미도 확인해요. 원본이 덮어써지면 실패예요.
8. **시간과 날짜:** 오전/오후, 12시/1시, 00분/59분으로 바꾸고 선택 띠/표시값/저장값을 대조해요. 시간 미정에서 처음 열 때도 확인해요. 월말, 윤년 2월, 날짜 변경과 지난 날짜의 홈 안내를 확인해요.
9. **다량 목록:** 가상 자료 90일 추가→7/30/90일 건수와 시작/종료일 확인→각 페이지 이동→상세→뒤로→캘린더. 같은 날 여러 기록도 구분돼야 해요. 삭제 테스트는 별도 복구 가능한 사본으로 준비해요.
10. **실제 보고서:** 동의와 코드를 준비하고 가상 7/30/90일을 각 한 번 생성해요. 기간/건수/대기 안내/전체 상태 중심 문장/금지된 과장 유무를 확인해요. 7일 생성 후 목록→90일 선택으로 UX-08도 확인해요. 성공 보고서를 재실행 후 열었을 때 AI 요청 수가 증가하면 실패예요.
11. **실패 복구:** 테스트 중계 서버에서 지연/오프라인/요청 제한/검증 실패를 각각 발생시켜요. 실패 원인과 다음 행동이 보이고 기존 자료가 남아야 해요. 화면을 나갔다 돌아와도 무한 자동 요청이 없어야 해요.
12. **PDF 공유:** 저장 보고서→PDF 공유→파일에 저장→파일 앱에서 열기. 짧은 본문, 여러 페이지, 긴 단어/괄호/특수문자, HTML처럼 보이는 가상 문구를 모두 포함해요. 본문과 기간/건수/생성일이 앱과 같고 한글/문장 끝/페이지 경계가 잘리지 않아야 해요.
13. **PDF 인쇄:** 실제 AirPrint 프린터에서 한 번 출력하고, 별도로 인쇄창을 취소해요. 취소가 실패처럼 나오지 않고 프린터 오류는 적절히 안내돼야 해요. Android는 인쇄 서비스와 PDF 저장을 확인해요. 재출력 전후 AI 카운터는 같아야 해요.
14. **파일 저장 취소:** iOS 공유창과 Android 폴더 선택을 취소해요. 취소 후 기존 보고서가 유지되고, 외부 폴더에 저장하지 않았는데 저장 완료라고 안내하지 않는지 확인해요. 실제 선택한 폴더에서 다시 찾을 수 있어야 해요.
15. **스크린리더:** VoiceOver/TalkBack을 켜고 탭, 같은 날 같은 유형의 기록 두 건, 날짜와 시간휠, 동의/삭제 모달을 순서대로 탐색해요. 버튼 이름만으로 구분되고 선택값이 읽혀야 해요. 모달 밖 요소로 초점이 빠지거나 닫은 뒤 초점이 사라지면 기록해요.
16. **알림:** 권한 거부→앱 안내→기기 설정 허용→매일 알림 설정. 앱 종료 후 예약 시간 수신과 탭 후 이동을 확인해요. 기록한 날에도 오는 매일 고정 알림은 기존 합의에 맞는 동작이에요. 일정 변경/삭제 시 전날 알림이 갱신되는지 확인해요.
17. **첫 실행 체험:** 실제 테스트 기록 수와 AI 설정을 메모→개발자 설정의 첫 실행 흐름 보기→임시 선택→테스트 종료. 원래 단계/체크리스트/기록/AI 동의와 코드가 유지돼야 해요. 자동 테스트는 격리 저장 구조를 확인했지만 이번 브라우저에서 체험을 새로 실행하지는 않았어요.
18. **초기화:** 실제 자료가 없는 별도 설치에서만 확인해요. 취소하면 모든 자료 유지, 실행하면 기록/초안/동의/코드/보고서/앱 내부 PDF 제거, 외부로 저장한 PDF 유지가 기준이에요. 이번 감사에서는 초기화 확인 화면만 열고 취소했어요.
