# AI 문장 지침 개선 및 검증 (2026-11-04)

종합 보고서의 현재 본문 구성과 재생성 제거 정책은 `docs/report-overview.md`를 따른다. 아래 기록 내용/정리 구분 예시는 이전 저장본의 호환성 테스트 사례이며 새 보고서의 목표 형식이 아니다.

## 문체 검사 완화와 실패 원인 분석

기존 검사는 정상적인 의미의 요약도 `요.`로 끝나지 않거나, 두 문장으로 나뉘거나, 전체 길이가 240자를 넘으면 거부했다. 원문 단어와 요약 단어의 일치율 검사는 없었다. 이 조건은 로컬 코드와 예시로 재현했다. 다만 사용자가 실제로 실패한 호출의 AI 응답과 세부 실패 코드는 기존 메시지에 남아 있지 않아 해당 호출이 이 중 어느 조건 때문이었는지는 확정할 수 없다. 실패 응답의 JSON 형식과 보고서 근거 ID 문제도 같은 오류로 묶여 있었다.

완화 후 -요 체, 한 문장, 마지막 마침표는 작성 프롬프트의 원칙으로 유지한다. 어미 차이와 두 문장이 섞인 결과는 문체만을 이유로 거부하지 않는다. 문장을 억지로 이어 붙이거나 첫 문장만 남기지 않는다. 줄바꿈을 공백으로 바꾸고, 제목과 바깥 따옴표, 마침표를 정리한다. JSON 전체를 감싼 코드 블록은 제거하고 다시 JSON으로 해석한다. 임의의 설명문에서 JSON 일부를 추출하거나 손상된 내용을 지어내 복구하지 않는다.

권장 30~70자는 거부 조건이 아니다. 기존 240자 상한은 서버와 앱 모두 1000자의 비정상 응답 방지 상한으로 조정했다. 상한을 넘으면 자르지 않는다. 한 줄 요약의 출력 토큰 한도는 300에서 800으로 조정했고 보고서 한도는 유지했다.

한 줄 요약은 과거에 내용상 근거 검증을 별도로 하지 않고 주로 프롬프트에 의존했다. 이번에는 `summary-evidence.js`에서 고위험 추가만 보수적으로 확인한다. 일반 단어의 일치나 원문 그대로의 인용을 요구하지 않는다. 원문에 없는 주요 진단/상태 용어, 전적인 도움 등 도움 정도의 확대, 매일/항상과 같은 빈도 확대, 새로운 횟수/기간 수치와 등급 예측을 거부한다. `두 번 ↔ 2차례`, `한 시간 ↔ 60분`, `절반 ↔ 50%`처럼 동등한 표현은 허용한다. 보고서의 근거 ID, 중복과 누락, 단일 기록을 반복으로 표시하는 검사는 유지한다.

이는 제한된 위험 표현 검사이며 모든 사실 관계를 의미상 증명하는 시스템은 아니다. 다른 진단명, 새로운 수치가 어느 동작에 해당하는지, 부정이나 추측의 의미 변경 등 모든 오류를 완벽히 감지한다고 주장하지 않는다. 원문 확인 안내와 작성 프롬프트를 유지한다. 정상 의역과 알려진 고위험 추가를 구분하는 회귀 테스트를 추가했다.

서버는 다음부터 `summary-format`, `summary-length`, `summary-medical`, `summary-assistance`, `summary-frequency`, `summary-count`, `summary-grade`, `response-json`, `response-schema`, `report-evidence` 등의 안전한 실패 사유만 반환한다. 앱은 이를 구체적인 안내로 표시한다. 원문, AI 응답 본문과 API 키는 오류 응답이나 로그에 남기지 않는다. 실패 시 기존 원문 표시와 수동 재시도를 유지한다.

추가 검증: `팔과 등을 받쳐드림 → 부축해드렸어요`, 숫자와 한글 횟수, 240자 초과 정상 문장은 통과한다. 원문에 없는 우울증, 인지 저하, 한 번을 세 번으로 확대, 오늘을 매일로 확대, 반찬만 잘라준 기록을 전적인 도움으로 확대, 등급 예측은 각각 별도의 실패 사유로 거부한다. 가상 중계 응답으로 사유 코드 반환, 앱에서의 원본 보존과 안전한 대체 표시 상태, 긴 요약의 온전한 저장을 확인했다. 실제 배포된 Claude 호출 결과를 읽거나 재현한 검증은 아니다.

## 변경 범위

- `workers/src/protocol.js`: 공통 `SYSTEM`, 한 줄 요약 `SUMMARY_INSTRUCTION`, 보고서 `REPORT_INSTRUCTION`. JSON 응답 형식, 근거 ID 체계와 처리 한도는 유지한다.
- `workers/src/writing.js`: 새로 도착한 AI 응답의 표현 형식만 정리하고 검사한다.
- `workers/src/summary-evidence.js`: 원문과 AI 요약 사이 고위험 추가 검사와 수치 표현 정규화.
- `workers/src/index.js`: 세부 실패 사유를 반환하고 안전한 JSON 코드 블록 보정을 연결한다.
- `src/features/records/ai-client.ts`: 실패 사유별 안내와 서버와 일치하는 1000자 상한. 저장 스키마는 그대로다.
- `workers/test/writing.test.mjs`: 예시 입력과 수동 검토한 기대 문장, 후처리 및 보고서 근거 회귀 테스트.
- `workers/test/relay.test.mjs`: 중계 흐름의 가상 AI 응답을 새 문체로 갱신한다.
- `workers/scripts/benchmark.mjs`: 모의 보고서 문장을 새 문체로 갱신한다.

앱의 오류 안내와 요약 상한 외에 저장 스키마, 접근 코드와 동의, 원본 저장 흐름, 기간 선택, PDF 처리와 참고자료 고지는 변경하지 않았다.

## 지침과 후처리

공통 지침은 본문의 자연스러운 -요 체와 마침표, 관찰과 추측 구분, 중요한 시간과 횟수 및 도움 정도 보존, 독립 수행, 기록 공백과 자료 부족을 명시한다. 없는 진단, 상태 변화, 장애 정도나 등급을 추정하지 않는다. 예시의 사실을 실제 입력에 섞지 않도록 명시한다.

한 줄 요약은 30~70자를 권장하되 중요한 사실을 빼서 맞추지 않는다. 1000자 방어 상한의 초과 응답은 자르지 않고 거부한다. 불필요한 `요약:`과 `한 줄 요약:`, 맨 앞 번호나 글머리표, 전체를 감싼 따옴표만 제거한다. 끝 마침표의 누락과 중복을 정리한다. 내부 발언의 따옴표나 원문 속 숫자는 임의로 삭제하지 않는다. 문체 검사를 완화해 -요 체가 아닌 어미나 형식적인 서두, 두 문장이 섞여 있어도 버리지 않는다. 줄바꿈은 공백으로, 가운데점은 쉼표로 정리하며 모든 문장 내용을 보존한다. 어미를 기계적으로 고쳐 사실을 바꾸지 않는다. -요 체 한 문장은 프롬프트로 계속 유도한다. 빈 응답, 잘못된 데이터 형식과 방어 상한 초과는 계속 거부한다.

보고서는 기존 `text` 안에서 `기록 내용: ...요.\n정리: ...요.` 형식으로 원문 사실과 기록에 한정한 정리를 구분하도록 요청한다. 제목에는 -요를 강요하지 않는다. -요 체는 프롬프트로 유도하되 어미가 다르다는 이유로 보고서 전체를 실패 처리하지 않는다. 문단 끝 마침표와 가운데점 표현만 정리한다. 원래의 ID 검증과 최소 두 기록의 반복 근거 검사는 유지한다. 사실성과 공통 상황의 의미상 정확성은 코드만으로 보증하지 않으며 사용자 원문 대조가 필요하다. 잘못된 응답은 자동 재호출하지 않는다.

## 예시 점검

아래는 실제 Claude가 생성한 결과가 아니라, 사용자가 제공한 입력으로 수동 검토하고 테스트에 넣은 기대 문장이다. 실제 서비스 키와 개별 접근 코드를 조회하거나 전송하지 않았으며 Claude를 직접 호출하지 않았다.

| 입력 상황 | 검토한 기대 문장 | 확인 사항 |
| --- | --- | --- |
| 아침에 침대에서 혼자 일어나기 어려워 팔을 잡아 일으켜드림 | 아침에 침대에서 혼자 일어나기 어려워하셔서 팔을 잡고 일으켜드렸어요. | 시간, 행동의 어려움과 실제 도움 보존 |
| 점심은 혼자 드셨지만 반찬을 흘려 식사 후 정리 | 점심 식사는 혼자 하셨지만 반찬을 자꾸 흘리셔서 보호자가 식사 후 주변을 정리했어요. | 독립 식사를 보호자의 식사 보조로 바꾸지 않음 |
| 저녁에 평소보다 말씀이 적고 식사는 절반 정도 | 저녁에 평소보다 말씀이 적으셨고 식사는 절반 정도 드셨어요. | 우울증, 인지 저하, 식욕부진 진단 추가 없음 |
| 혼자 화장실 이용, 별도 도움 없음 | 오늘은 혼자 화장실에 다녀오셨고 별도의 도움은 필요하지 않았어요. | 도움 없음과 독립 수행 보존 |

가상 보고서 입력은 11월 3일의 침대에서 일어날 때 팔을 받친 기록(a), 11월 4일의 팔을 잡아드린 기록(b), 같은 날의 독립 식사 기록(c)이다. 수동 검토한 기대 출력은 다음과 같다.

- 제목 `침대에서 일어나기`: `기록 내용: 침대에서 일어나실 때 팔을 받쳐드리거나 잡아드렸어요.`와 `정리: 서로 다른 날짜의 기록에 일어설 때 제공한 도움이 남아 있어요.`로 구분한다. 근거 a, b이며 반복 표시가 허용된다.
- 제목 `식사`: `기록 내용: 점심은 혼자 드셨어요.`와 `정리: 이 기록만으로 다른 식사의 도움 여부는 알 수 없어요.`로 구분한다. 근거 c이며 반복으로 표시하지 않는다.
- 같은 반복 설명을 근거 하나만 연결해 보내면 거부한다. 제목은 그대로 유지하고 본문에만 -요 체를 적용한다. 형식 보정 중 근거 ID와 원문 스냅샷이 바뀌지 않는지 검사한다.

후처리는 위 요약에 바깥 따옴표, `요약:`, 번호, 마침표 누락이나 중복을 넣어도 같은 완전한 문장을 반환하는지 확인한다. 70자를 넘더라도 중요한 정보를 자르지 않는다. 두 문장을 한 문장처럼 첫 문장만 남기는 처리는 하지 않는다.

## 적용 방식과 운영

- 기존 원문과 저장된 AI 요약은 그대로다. 새 요약을 만들거나 사용자가 요약 다시 만들기를 선택한 경우에만 새 지침이 적용된다.
- 기존 보고서의 저장된 본문은 그대로다. 본문을 먼저 보여주고 근거를 뒤에서 확인하는 화면/PDF 배치는 기존 저장본에도 적용된다. 같은 기간 다시 생성 버튼은 제거했으며 저장된 기간은 AI 호출 없이 재사용한다. 새 지침은 아직 저장본이 없는 기간의 새 보고서에 적용된다. 자동 재생성이나 일괄 전송은 하지 않는다.
- AI 미동의, AI 사용 중지 또는 실패 시의 기존 원문 대체 요약은 변경하지 않는다. 대체 표시까지 -요 체로 자동 변환하지 않는다.
- 서버 프롬프트와 검증을 변경했으므로 **Workers 재배포가 필요하다**. `cd workers` 후 `npm run deploy`를 실행한다. 기존 Secret과 모델 설정을 유지하고 키를 다시 앱에 입력하지 않는다. 실제 배포는 이번 작업에서 수행하지 않았다.
- 실제 배포 모델에서의 문장 품질과 사실 보존은 추가 확인이 필요하다. 위 네 입력과 가상 보고서 자료를 사용해 원문, 요약과 근거 ID를 대조한다. 실데이터나 API 키를 채팅에 붙여 넣을 필요는 없다.
