# 감사 후속 수정과 검증 결과

기준일: 2026-11-05. 감사 후 사용자가 승인한 수정과 이어서 요청한 설문 뒤로가기 및 말풍선 개선을 포함한다. 같은 작업 트리에서 진행 중이던 다른 수정은 보존했다. 커밋, 패키지 설치, 운영 Workers 배포와 유료 Claude 호출은 수행하지 않았다.

## 1. 설문 뒤로가기 집중 수정

수정 전 실패하는 테스트를 먼저 작성해 다음 세 조건을 재현했다.

1. 개인화 설문 완료 시 질문 이력을 빈 배열로 바꿔, 완료 후 복귀에 사용할 질문 순서가 사라졌다.
2. 실제로 거친 질문이 이후 수동 완료 또는 기존 체크 상태 때문에 질문 후보에서 제외되면 뒤로가기 이력에서도 삭제됐다. 직전 질문 대신 더 앞선 질문으로 건너뛰었다.
3. 의사소견서 준비 중 → 제출기한 미정 → 다음 질문에서 뒤로 돌아온 뒤 같은 답으로 진행하면, `deadlineAsked`만 보고 제출기한 질문을 건너뛰었다.

수정 내용:

- 실제로 방문한 질문과 답변을 기준으로 이전 질문을 복원한다. 이미 방문한 질문은 체크 완료 표시만으로 이력에서 제거하지 않는다.
- 설문 완료 후에도 질문 이력을 보관한다. 완료한 안내가 자동으로 재개되지는 않으며 명시적인 설문 복귀에서만 완료 이력을 사용한다.
- 제출기한 응답을 기존 `answers` 구조의 `medical-deadline` 항목으로 함께 보관해, 같은 답변으로 다시 진행할 때 실제 질문 경로를 유지한다.
- 첫 질문의 뒤로가기는 해당 설문에 진입한 단계 선택 화면으로 돌아간다. 문답형 단계 발견 경로로 실제 진입한 경우에만 그 경로를 사용한다.
- 단계 화면의 `review` 파라미터가 바뀌어도 처음 초기화된 화면 모드에 고정되지 않게 했다.
- 저장 또는 다음 진행과 뒤로가기가 동시에 커서를 수정하지 않도록 공통 이탈 훅에 동작 차단 조건을 추가했다. UI의 busy 렌더링 전에도 저장 잠금을 확인한다.
- 기존 기록, 체크리스트 메모, AI 동의 및 보고서 저장 형식을 바꾸지 않는다.

실제 웹 조작 결과:

- `신청 방법 → 갱신 시기 → 신청 목적 → 신청 경험 첫 질문` 순서로 연속 뒤로가기.
- 갱신 시기의 ‘아직 확인하지 않았어요’, 신청 목적의 ‘갱신’, 첫 질문의 ‘전에 신청한 적 있어요’ 선택 복원 확인.
- 첫 답변을 ‘처음 신청’으로 수정 후 신청 대상 질문으로 새 분기 확인.
- 첫 질문에서 다시 뒤로 갔을 때 기존 선택이 유지된 단계 선택 화면으로 이동. 홈으로 이동하지 않음.
- 의사소견서 미제출 → 제출기한 미정 → 결과 확인 질문에서 역순 복귀 확인. 같은 미제출 답으로 다시 진행해도 제출기한 질문 유지.
- 설문 완료 후 홈의 ‘이전 질문으로 돌아가기’로 마지막 질문을 다시 연 뒤, 직전 질문과 기존 선택 복원 확인.

이 조작은 8093 격리 origin의 첫 실행 테스트에서 했다. 실제 iOS 스와이프 및 Android 하드웨어 뒤로가기는 기기 검증이 남아 있다. 공통 처리의 잠금과 질문 순서는 자동 테스트로 확인했다.

## 2. 기록 안내와 첫 홈 진입

- 돌봄기록 안내의 주요 버튼을 ‘확인했어요’로 변경했다.
- 확인 후 `/records`로 바로 이동하지 않고 준비 체크리스트가 있는 `/home`으로 이동한다.
- 처음 안내 완료 직후에만 기록 탭을 녹색 테두리로 강조하고 안내 말풍선을 표시한다.
- 말풍선 꼬리는 기록 탭 중심을 가리킨다. 화면에서 꼬리와 탭 강조를 직접 확인했다.
- 안내는 약 10초 후 또는 탭 선택 시 닫힌다. 깜빡임과 반복 애니메이션을 사용하지 않는다.
- 완료 상태는 기존 `completionGuide`로 유지하고 강조 상태는 해당 실행의 임시 상태로만 관리한다. 재실행 시 기존 사용자에게 안내를 다시 강제하지 않는다.

파일: `src/features/preparation/completion-screen.tsx`, `src/features/preparation/provider.tsx`, `src/app/(tabs)/_layout.tsx`.

## 3. 보고서 화면과 PDF

- 사용자의 최종 선택에 따라 앱 화면과 PDF 모두 근거 기록 목록, 근거 원문 부록 및 본문별 참조 목록을 제거했다.
- 제목, 보고서 기간, 분석 기록 수, 생성일, 종합 본문, 참고자료 안내는 유지한다.
- 내부 근거 ID 검증, 생성 당시 원문 스냅샷, 기록 변경 감지와 기존 저장 보고서는 유지한다. 근거 목록을 숨겼다는 이유로 검증을 없애지 않았다.
- 기존 보고서를 새 형식으로 열거나 PDF로 내보내는 데 AI 재호출은 없다. 이미 외부에 저장된 PDF 파일을 자동 수정하지 않는다.
- 보고서 생성 중 실제 단계인 확인, AI 응답 대기, 검증 및 저장, 완료를 구분한다. 경과 시간은 표시하지만 가짜 백분율은 만들지 않는다.
- 생성 시작 시 처리 상태가 보이도록 위로 이동하고, 실패하면 원인 문구를 확인 대화상자로 표시한다. 오류 문구가 긴 보고서 목록 아래에 묻히는 문제를 방지한다.
- 자동 재요청이나 유료 보정 호출은 추가하지 않았다.

파일: `src/features/records/reports-screen.tsx`, `report-content.tsx`, `report-html.ts`, `report-pdf.ts`, `report-progress.tsx`, `report-progress-state.ts`, `ai-client.ts`.

### 90일 보고서 문제에서 확인된 사실

사용자는 재배포 후 7일과 30일 생성 성공, 90일의 수치 검증 실패 및 같은 원본으로 재시도 후 성공을 보고했다. 이는 매 요청의 생성 문장이 달라져 검증 결과도 달라질 수 있음을 보여준다. 실패한 AI 본문을 수집하거나 로그로 출력하지 않았으므로 어떤 숫자가 문제였는지, 그 숫자가 실제 왜곡인지 단위 표현 차이의 오탐인지는 확정하지 않았다.

필수 항목 및 ID 목록 형식 문제를 줄이기 위해 보고서 API 요청에 고정 JSON Schema 구조화 출력을 추가했다. 존재하지 않는 ID, 누락 근거, 근거 없는 수치와 진단 등의 검증은 유지한다. `ALL`의 대소문자 및 주변 공백 차이만 안전하게 정규화한다. 이 수정이 수치 검증 실패를 모두 없애거나 실제 90일 생성의 성공을 보장하는 것은 아니다.

고정 스키마는 기간 및 기록 수마다 변경하지 않으므로 기록 본문이나 개별 ID를 스키마에 넣지 않는다. 첫 스키마 사용 시에는 공급자 측 형식 준비로 추가 시간이 들 수 있다. 현재 설정 모델은 공식 문서의 지원 대상이지만 서버 모델 변경 시 구조화 출력 지원 여부도 확인해야 한다. [Anthropic 구조화 출력](https://platform.claude.com/docs/en/build-with-claude/structured-outputs).

서버 파일: `workers/src/report-output-format.js`, `workers/src/index.js`, `workers/src/report-response.js`. `workers/test/report-format.test.mjs`에서 90개 원본의 전송, ALL 복원, 잘못된 수치 거절을 확인했다.

한 줄 요약의 정상 의역을 더 엄격하게 제한하는 검사는 추가하지 않았다. 도움 유무의 의미 역전 문제는 기존 감사의 미해결 항목이며, 단어 일치 점수로 막는 방식은 권장하지 않는다. 문장 형식과 사실 검증을 구분하고 명확한 모순 반례를 중심으로 보완하는 것이 다음 과제다.

## 4. 요약 버튼의 이용 상태

- 기존 상세 버튼은 동의와 주소만 확인하고 접근 코드 등록 여부를 반영하지 않았다. 현재는 저장된 동의와 코드, 유효한 HTTPS 주소, 상태 읽기 실패를 구분한다.
- 상태가 준비되면 버튼이 활성화되고, 사용할 수 없으면 그 실제 이유를 표시한다.
- 설정 변경 시 재조회하고 저장소 읽기 실패에는 ‘AI 이용 상태 다시 확인’을 제공한다.
- 상세 화면에 코드 입력이나 동의 관리 카드를 다시 넣지는 않았다.

파일: `src/features/records/ai-controls.tsx`, `summary-readiness.ts`.

## 5. 초기화 범위

- AsyncStorage와 알림 외에 접근 코드와 앱 Documents의 `reports` 디렉터리를 초기화 대상에 추가했다.
- 사용자가 직접 선택한 외부 폴더나 공유한 파일은 탐색하거나 삭제하지 않는다. 확인 화면에도 이 범위를 안내한다.
- 삭제 실패 시 기존 초기화 저널을 남겨 다음 실행에서 재시도할 수 있게 한다.
- PDF 출력과 코드 저장을 기존 데이터 작업 게이트에 연결했다. 초기화가 진행 중 작업을 기다리고, 예전 작업이 나중에 코드를 되살리는 경합을 방지한다.

파일: `src/features/reset/private-assets.ts`, `private-assets.web.ts`, `controller.ts`, `provider.tsx`, `settings-reset.tsx`, `src/features/records/report-pdf.ts`, `ai-client.ts`.

모의 SecureStore 및 파일 시스템으로 삭제 범위, 잠긴 파일 실패, 재실행 복구, 진행 중 작업 대기를 검증했다. 실제 사용자 자료를 초기화하지 않았다. 네이티브 실제 파일과 Keychain 삭제는 별도 확인이 필요하다.

## 6. 매일 알림

- 사용자가 선택한 정책에 따라 돌봄 알림을 30일치 개별 예약에서 시스템 매일 반복 예약으로 변경했다.
- 앱을 30일 이상 열지 않아 예약이 소진되는 구조를 제거했다.
- 기록을 작성한 날에도 알림이 오며, 방문 전날 알림과 같은 날에도 둘 다 올 수 있다. 설정에 작성한 날에도 알림이 온다는 설명을 표시한다.
- 기존 개별 예약은 다음 앱 실행 시 반복 예약으로 정리한다. 시간 변경, 알림 끄기, 권한 철회와 복구, 중복 예약 방지를 테스트했다.
- 운영체제 절전, 권한 제한 및 기기 환경에 따른 실제 전달 지연까지 보장하는 것은 아니다.

파일: `src/features/notifications/planner.ts`, `native.ts`, `service.ts`, `provider.tsx`, `tests/notifications.test.cjs`.

## 7. 기록 페이지와 줄바꿈

- 기록을 계속 추가하는 더 보기 방식 대신 한 페이지 10건의 이전 및 다음 이동으로 변경했다.
- 기간 또는 날짜 변경 시 첫 페이지로 돌아가고, 삭제 후에는 유효한 마지막 페이지로 보정한다. 날짜 제목과 방금 저장한 기록 강조를 유지한다.
- 90건 분할의 중복 및 누락 방지를 자동 검증했다. 웹에서는 가상 자료 90건과 기존 가상 기록 2건으로 92건, 10페이지 표시와 다음 페이지의 기록 교체를 확인했다.
- 화면에 렌더링하는 목록을 제한한 것이며 전체 저장소 읽기를 데이터베이스 페이지 조회로 변경한 것은 아니다.
- 주요 설정과 기록 및 보고서 문구에 한글 단어 단위 줄바꿈을 적용했다. iOS의 한글 줄바꿈 속성과 웹의 keep-all을 사용하고, Android는 highQuality를 유지한다. 원문에 공백이나 줄바꿈 문자를 삽입하지 않는다.

파일: `src/features/records/pagination.ts`, `records-browser.tsx`, `review-screen.tsx`, `src/components/readable-text.ts` 및 주요 설정, 알림, AI 화면.

## 8. 개인정보처리방침과 설치 이름

- 설정과 AI 동의 안내에서 앱 내 개인정보처리방침을 열 수 있게 했다. 오프라인에서도 앱에 포함된 문서를 읽는다.
- 운영자 표시에는 ‘장기요양길잡이 운영자’, 문의처에는 사용자가 제공한 이메일을 사용했다. 알 수 없는 개인 실명이나 법인명은 만들지 않았다.
- 기기 저장, AI 외부 전송과 해외 처리, 처리 사업자, 인증 및 호출 제한 메타데이터, 동의 철회, 삭제 범위, 문의와 정책 변경을 설명한다.
- 실제 계약을 확인하지 않은 외부 AI 보관 기간을 임의로 0일 또는 30일로 단정하지 않았다. 정식 출시 전 실제 운영자 정보와 계약 및 해외 처리 고지는 확정해야 한다.
- 앱과 같은 원문에서 생성한 공개 웹페이지 파일을 준비했다. 공개 배포 연결 권한이 승인되지 않아 **실제 공개 URL 배포는 완료하지 않았다.** 예약된 사이트 주소를 사용 가능한 공개 URL이라고 보고하지 않는다.
- 공개 페이지 소스는 `sites/privacy/dist/index.html`, 재생성 명령은 프로젝트 루트에서 `node scripts/build-privacy.cjs`다. 이 디렉터리는 다른 정적 호스팅에도 업로드할 수 있다.
- Sites 프로젝트 ID는 `sites/privacy/.openai/hosting.json`에 보존했다. 재개 시 새 사이트를 중복 생성하지 않는다. 인증 토큰은 파일로 보관하지 않았다.
- Expo 설치 이름을 `장기요양길잡이`로 변경했다. slug와 영구 앱 식별자는 임의로 변경하지 않았다. 네이티브 설치 이름 반영에는 새 앱 빌드가 필요하며 Expo Go 앱 자체 이름을 변경하는 것은 아니다.

파일: `src/features/privacy/policy.ts`, `privacy-screen.tsx`, `src/app/privacy.tsx`, `src/app/(tabs)/settings.tsx`, `src/app/_layout.tsx`, `scripts/build-privacy.cjs`, `sites/privacy`, `app.json`.

개발자 메뉴의 출시 위치 변경과 일반 사용자 인증 및 기능별 이용 한도는 사용자가 보류했으므로 이번에 전환하지 않았다. 설문의 기존 질문 및 분기 체계를 새로 설계하지 않았다.

## 10. 사용자가 수행할 배포

**설문 뒤로가기, 말풍선, 목록 숨김, 초기화와 알림 같은 앱 변경은 앱 업데이트로 반영한다. 서버의 보고서 구조화 출력과 배포 식별은 Workers 재배포가 필요하다.**

프로젝트의 `workers` 디렉터리에서:

```powershell
cd C:\Users\khs13\care-diary\workers
npx.cmd wrangler deploy
```

이 변경만으로 기존 Claude 키와 접근 코드 Secret을 새로 발급하거나 채팅에 전달할 필요는 없다. 기존 Workers의 올바른 계정 및 프로젝트에 배포해야 한다.

배포 뒤 중계 주소의 `/health`를 열어 다음 필드를 확인한다. 이 확인은 Claude를 호출하지 않는다.

```json
{"protocolVersion":"2026-11-05.1","reportEvidence":"short-ids-and-all"}
```

이 응답은 코드 버전 확인이며 실제 Claude 호출 성공, Secret 유효성이나 90일 보고서 품질 보증은 아니다. 원문, AI 응답, API 키는 이 진단 응답에 포함되지 않는다.
