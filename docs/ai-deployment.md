# AI 요약, 기간 보고서와 PDF 운영 안내

## 구현과 저장

기존 `care-diary:situation-records:v2` 저장소와 설문 분기를 유지한다. 직접 작성과 질문 작성은 같은 저장 함수를 사용한다. 원본 쓰기가 성공한 뒤 비동기로 한 줄 요약을 요청한다. 실패해도 원본 쓰기 결과는 성공이다. 기존 기록은 일괄 전송하지 않는다. 상세에서 직접 요청할 수 있다.

AI 동의는 별도 `care-diary:ai-consent:v1` 키에 버전과 함께 저장한다. 기능 소개 완료와 동의를 연결하지 않는다. 동의 전 전송하지 않으며 철회 후 도착한 결과도 저장하지 않는다. 전송을 이미 시작한 요청의 내용을 외부에서 회수할 수는 없다. 기록 본문은 Cloudflare와 Anthropic으로 전송되므로 불필요한 개인정보를 입력하지 않도록 안내한다.

요약은 기록 내부 `aiSummary`에 저장한다. 원문 내용의 정확한 fingerprint와 요청 ID를 모두 비교하고, 존재하는 기록의 AI 필드만 갱신한다. 수정 전 응답과 삭제한 기록의 응답은 무시한다. 처리 중 수정된 내용은 이전 요청 종료 후 한 번 새로 요청한다. 동일 원문 실패는 자동 재시도하지 않는다. 앱 재시작 당시 처리 중이던 요약은 실패 상태로 바꿔 사용자가 다시 생성할 수 있게 한다.

보고서는 `care-diary:ai-reports:v1`에 기간, 생성일, 모든 근거 원문 스냅샷, 근거 ID와 AI 본문을 저장한다. 다시 열기와 PDF 출력에는 AI 호출이 없다. 같은 시작일과 종료일의 보고서가 이미 있으면 저장본을 재사용하며 다시 생성 버튼은 제공하지 않는다. 기간 내 원문, 날짜, 유형 또는 기록 목록이 바뀌면 생성 후 기록 변경 안내만 표시한다. 보고서는 자동 갱신하지 않는다. 원본 삭제 후에도 기존 보고서에는 생성 당시 근거가 남는다. 앱 전체 초기화 시 동의, 보고서, 원본은 기존 초기화 방식으로 삭제된다. SecureStore 접근 코드는 전체 초기화 후 남을 수 있으나 동의가 지워져 자동 전송하지 않는다. 접근 코드 삭제는 AI 이용 설정에서 별도로 제공한다.

## 접근 통제와 한도

접근 코드 등록은 `POST /access/verify`에서 서버 허용 여부를 확인한 뒤 SecureStore에 저장한다. 형식 오류, 잘못된 코드, 네트워크 오류, 서버 미설정과 등록 완료는 앱 확인창으로 구분한다. 검증 실패 시 기존 저장 코드는 유지한다. 이 엔드포인트는 돌봄기록을 전송하거나 Claude를 호출하지 않으며 동일 서버 호출 제한을 적용한다. 기존 Worker를 운영 중이면 `cd workers` 후 `npm run deploy`로 업데이트해야 한다. 이전 서버의 404를 등록 성공으로 처리하지 않는다.

앱에 공통 비밀이나 Claude 키를 넣지 않는다. 초기 소규모 운영에서는 관리자가 승인한 사용자/기기별 무작위 256비트 접근 코드를 발급한다. 앱에는 사용자가 자신의 코드를 입력하며 네이티브 SecureStore에 저장한다. 웹에서는 메모리에만 두므로 새로고침 후 다시 입력한다. 서버에는 코드 원문이 아닌 SHA-256 해시 목록을 Secret으로 둔다. 이 코드는 Claude API 키와 다르다.

계정 가입이 있는 대규모 공개 앱용 자동 등록 시스템은 아니다. 승인된 사람에게 개별 발급하는 방식이다. 코드 유출 시 해당 해시를 즉시 제거하고 새 코드를 발급한다. 공개 가입이 필요해지면 별도 사용자 인증과 서버 발급 토큰 체계를 붙여야 한다.

SQLite 기반 Durable Object 하나에서 계수기를 원자적으로 관리한다. 유효 코드당 분당 4회, UTC 하루 30회, 같은 IP 분당 20회, 전체 UTC 하루 기본 100회다. 거부 요청도 한도를 소모할 수 있다. 전체 일 한도는 서버 `DAILY_GLOBAL_LIMIT`으로 최대 500까지 설정 가능하다. 원문, 결과와 API 키는 Durable Object에 저장하지 않는다. 저장값은 해시 식별자, 시간 버킷과 횟수뿐이다. 서버 `console` 출력과 Workers 관측 로그를 사용하지 않는다. 대시보드에서 별도 본문 로깅이나 외부 로그 수집을 켜지 않는다.

요청은 실제 스트림의 UTF-8 크기 96,000바이트, 최대 300건, 기록당 20,000자까지다. 보고서 범위는 최대 90일이며 ID, 날짜와 기존 유형을 검사한다. 모든 원문을 보내거나, 초과 이유를 명시하고 아무것도 전송하지 않는다. 자동 분할은 하지 않는다. 더 짧은 기간을 선택해 다시 생성한다. 긴 단일 기록이 한도를 넘으면 원본은 유지되지만 현재 버전에서는 AI 생성할 수 없다. 프롬프트는 서버에서만 정의한다. 본문 안 명령을 데이터로 취급한다. 출력 ID의 유효성, 중복, 전체 근거 포함 여부와 반복 사례의 최소 2개 기록을 서버와 앱에서 검사한다. 의미상 사실성까지 자동으로 보증하지 않으며 사용자가 근거를 확인해야 한다.

## 사용자가 수행할 배포 순서

프로젝트 루트에서 시작한다. API 키나 개인 접근 코드를 채팅, Git, Expo 공개 환경변수에 넣지 않는다.

1. `cd workers` 후 `npm install`을 실행한다. 로컬 실행은 `npm run dev`, 테스트는 `npm test`다.
2. `npx wrangler login`으로 준비된 Cloudflare 계정에 로그인한다.
3. `wrangler.jsonc`의 `CLAUDE_MODEL`에 자신의 Anthropic 계정에서 사용할 수 있는 모델 ID를 설정한다. 화면에는 표시되지 않는다. 웹 앱도 운영하면 `ALLOWED_ORIGIN`에 정확한 웹 원점을 설정한다. 네이티브 앱만 사용하면 빈 값으로 둔다. 광범위한 `*` CORS는 허용하지 않는다.
4. `npx wrangler secret put ANTHROPIC_API_KEY`를 실행하고, 터미널의 비밀 입력 프롬프트에 Claude API 키를 입력한다. `.env`나 설정 파일에 키를 적지 않는다.
5. `node scripts/create-access.mjs`를 사용자/기기마다 한 번 실행한다. 출력되는 접근 코드 원문은 해당 사용자에게 안전하게 전달하고 관리한다. 출력되는 SHA-256만 다음 Secret 등록에 사용한다. 테스트 명목으로 실제 사용자 키를 저장소에 추가하지 않는다.
6. `npx wrangler secret put ACCESS_TOKEN_HASHES`를 실행하고 승인한 해시들을 쉼표로 연결해 입력한다. 재등록은 전체 목록을 교체한다. 발급 목록은 저장소 밖에서 관리한다. 이 Secret 값을 제거하면 모든 접근이 차단된다.
7. `npx wrangler deploy --dry-run`으로 번들을 확인한 뒤 `npm run deploy`로 배포한다. SQLite Durable Object 마이그레이션이 포함돼 있어 무료 플랜에서 시작할 수 있다. Secret 등록 시 첫 Worker가 자동 생성되는 CLI 흐름이 계정에서 지원되지 않으면 먼저 deploy한 뒤 Secret을 등록한다. 미설정 상태는 503으로 차단된다.
8. 배포된 HTTPS 주소를 앱 루트의 로컬 `.env`에 `EXPO_PUBLIC_AI_SERVER_URL=https://...workers.dev`로 설정한다. 앱의 공개 환경변수에는 이 주소만 넣는다. Metro를 재시작하고 배포용 앱에도 해당 주소를 반영한다.
9. 앱의 `설정 → 개발자 설정 → AI 이용 설정`에서 안내를 읽고 별도 전송 동의 후 개별 접근 코드를 등록한다. 동의와 실제 저장된 코드가 모두 확인되면 `접근 코드 삭제`, `동의 철회하기`만 표시한다. 코드 삭제는 동의와 기존 자료를 유지하고 입력창만 다시 표시한다. 동의 철회는 저장된 코드를 유지하지만 AI 요청을 차단하며, 재사용하려면 별도 전송 동의가 다시 필요하다. 기존 기록은 상세에서 요약을 선택한다. 이후 새로 저장하거나 수정한 기록은 원본 저장 후 자동 요약한다.
10. PDF와 SecureStore 네이티브 모듈, iOS 파일 공유 설정이 추가됐다. 배포용 바이너리를 다시 빌드한다. EAS 사용 시 프로젝트 루트에서 `npx eas-cli@latest build --profile development`로 개발 빌드를 준비한다. 이 저장소에 EAS 설정이 없으면 먼저 본인의 계정으로 EAS 프로젝트와 profile을 구성한다. 생성되는 `ios/`, `android/`는 직접 편집하지 않는다.
11. 아래 CPU와 실제 기기 검증을 마친 뒤 사용 범위를 늘린다. Workers 무료와 별개로 Claude API 사용에는 Anthropic 요금이 발생할 수 있다.

## 무료 플랜 CPU 확인

Cloudflare 공식 문서상 무료 Workers는 HTTP 요청당 CPU 10ms다. 외부 fetch와 저장소 응답을 기다리는 시간은 CPU에 포함되지 않는다. 따라서 Claude 생성에 걸리는 수십 초와 CPU 제한은 서로 다르다. 이 구현은 서버에서 LLM을 실행하거나 PDF를 렌더링하지 않는다. 유효성 검사, 해시와 JSON 중계만 한다. 96KB 상한과 Set 기반 근거 검증으로 작업량을 제한했다.

- `node scripts/benchmark.mjs`는 최대 300건의 가상 기록을 사용하는 Node 로컬 모의 측정이다. 실제 Cloudflare CPU 증명으로 사용하지 않는다.
- 배포 후 대시보드의 Worker Metrics에서 CPU time과 Errors의 Invocation Status를 확인한다. 실제 개인정보 없이 짧은 기록, 90일 최대 크기 가상 기록을 각각 생성한다. `Exceeded CPU Time Limits` 또는 `exceededCpu`, 오류 1102가 없는지 확인한다. 로그를 켜서 본문을 출력할 필요는 없다.
- 여러 차례의 실제 최대 입력 및 최대 응답에서 10ms를 넘거나 여유가 부족하면 `MAX_BYTES`와 앱 측 같은 한도를 함께 줄이거나 유료 Workers로 전환한다. 자동으로 무료 플랜 한도를 초과해도 정상 동작한다고 보장하지 않는다. 호출 실패 시 기기의 원본은 보존된다.

공식 근거: [Workers 제한과 CPU 계산](https://developers.cloudflare.com/workers/platform/limits/), [무료 SQLite Durable Objects](https://developers.cloudflare.com/durable-objects/platform/pricing/), [Anthropic Messages API](https://platform.claude.com/docs/en/api/messages).

## PDF

SDK 58 문서를 확인하고 Expo 설치 명령으로 `expo-print`, `expo-sharing`, `expo-file-system`, `expo-secure-store` 호환 버전을 설치했다. 저장된 보고서로 HTML을 생성하며 사용자 입력과 AI 출력 모두 HTML 이스케이프한다. 외부 웹 폰트나 이미지를 요청하지 않는다. OS 한글 글꼴을 사용하고 문단의 고아줄, 제목 뒤 페이지 나눔과 여백을 CSS로 제어한다. 원문 근거도 PDF에 포함한다.

Android 파일 저장은 시스템 디렉터리 선택기를 연다. iOS는 앱 Documents/reports에 복사하고 공유창에서 파일에 저장할 수 있다. 새 바이너리에서는 iOS Files의 앱 문서 공유도 활성화된다. 웹은 브라우저 인쇄 화면에서 PDF 저장을 사용한다. 캐시 PDF는 공유/저장 처리 후 삭제하며 저장한 문서 파일은 남는다. 파일 경로의 생성 성공과 실제 외부 공유 완료 여부는 다르다. 사용자가 공유창을 취소하면 실제 공유는 이루어지지 않는다.

## 실제 기기에서 추가 확인할 항목

- iOS와 Android에서 신규 직접 기록, 질문 기록, 기존 기록 수동 요약을 가상 자료로 확인한다.
- 비행기 모드와 잘못된 코드, API 오류 및 호출 한도 상태에서도 원본이 남는지 확인한다.
- AI 대기 중 원문 수정과 삭제, 동의 철회, 앱 종료 후 재시도를 확인한다.
- 같은 보고서를 닫았다 다시 열기, PDF 공유, 인쇄, 파일 저장 시 Claude 호출 횟수가 늘지 않는지 확인한다.
- 한글, 긴 한 문장과 여러 문단, 3페이지 이상, 페이지 끝 제목, 원문 특수문자 `<>&"'`가 정상 출력되는지 확인한다.
- iOS AirPrint와 공유창의 파일에 저장, Android 인쇄 서비스와 시스템 폴더 선택을 실제 기기에서 확인한다.
